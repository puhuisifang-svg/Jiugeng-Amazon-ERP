# 7 天观察运行手册

## 启动门禁

每个店铺均须满足：链接为公开美国站店铺；用途获批；数据源条款已复核；访问无需绕过控制；记录中只保存店铺标识的哈希/内部代号。任一项不满足，不启动该店观察。

## 每次运行

1. 创建唯一 `runId`，记录 Adapter 名称/版本、计划时间与内部店铺代号。
2. Adapter 返回状态、商品标识集合、分页/覆盖元数据以及受控原始证据引用。
3. 对照 `snapshot-manifest.schema.json` 写快照清单；原始正文不得提交 Git。
4. 执行完整性规则：成功状态、分页闭合、数量一致、唯一 ASIN、证据哈希存在。
5. 仅 `COMPLETE` 快照进入基线决策：无基线时建立；有基线时与最近有效基线比较。
6. 新品事件键固定为 `storeKey + marketplaceId + asin`；同一键重跑不得重复。
7. 写当日观察记录；失败原因不得用猜测补齐。

## 连续性口径

- 观察周期从首个 `COMPLETE` 且成功晋升的有效快照开始，连续 7 个自然日。
- 失败/不完整运行保留证据但不更新基线；当天可在合规限额内重试。
- 若数据源要求验证码、登录或明确拒绝自动访问，立即停止并建议人工导入。
- 第 7 天按模板计算成功率、覆盖率、误报、单次成本及人工工时，提交 Stage Gate 建议。

## 人工降级

自动路线不合规或稳定性不足时，使用经 PM 冻结的 Excel 模板人工导入。人工文件同样保留来源、批次、操作者和校验报告，不假装为自动采集成功。
