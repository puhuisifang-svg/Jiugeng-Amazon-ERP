# ERP-005 候选证据附件与安全导出计划

## 目标

补齐 MVP 选品范围中尚未完成的“附件”和“导出”能力，使选品人员能够在候选详情中登记可追溯的证据链接，并将当前筛选结果导出为安全、可审计的 CSV。

本批次继续使用 `SYNTHETIC` 内存数据，不上传真实文件，不访问附件内容，也不替代生产对象存储、病毒扫描或数据权限验收。

## 范围

### 1. 候选证据附件

- 在候选详情中展示证据附件元数据。
- `ADMIN`、`SELECTION` 可登记附件名称、HTTPS 链接和说明；`PRODUCT_MATERIAL` 只读。
- 记录添加人、角色和时间；附件只追加，不在本批提供覆盖或删除。
- 后端拒绝空名称、非 HTTPS 链接、超长字段和不存在的候选。
- 页面打开外部证据时使用安全的新窗口链接属性。

### 2. 候选 CSV 导出

- 候选池导出当前搜索、状态和负责人筛选后的结果，而不是无条件导出全部数据。
- 字段包括 ASIN、标题、状态、评分、类目、价格、星级、评论数、负责人、标签、选品理由、来源店铺、发现时间和淘汰原因。
- CSV 使用 UTF-8 BOM、标准双引号转义和稳定列顺序。
- 对以 `=`, `+`, `-`, `@` 开头的文本做公式注入防护。
- 无结果时禁用导出，并显示明确状态。

## 不在范围

- 二进制文件上传、下载代理、对象存储、病毒扫描、缩略图和附件删除。
- Excel/XLSX、定时导出、邮件发送和跨模块报表中心。
- 生产数据持久化、真实授权链接和外部附件可用性验证。

## 实施顺序

1. 扩展候选详情读模型，增加证据附件元数据与追加接口。
2. 补齐附件字段校验、角色权限、只追加语义和后端测试。
3. 在候选详情页增加附件登记与展示。
4. 抽取可测试的 CSV 编码器，在候选池增加“导出当前结果”。
5. 运行后端、前端、lint、typecheck、production build 和动态 HTTP 验收。

## 验收标准

- 合法 HTTPS 证据可追加，响应包含添加人、角色和时间。
- HTTP、空白或非法 URL 返回 400；产品/辅料角色写入返回 403。
- 旧附件不会因新增操作被修改或丢失。
- 候选详情页可展示并安全打开证据链接。
- CSV 只包含当前筛选结果，列顺序固定，逗号、双引号和换行转义正确。
- 公式注入样本导出后以文本处理，不会作为电子表格公式执行。
- 全部质量门禁通过，历史未提交材料不进入本批提交。

- 导出格式仅为 CSV，且导出当前筛选结果。
