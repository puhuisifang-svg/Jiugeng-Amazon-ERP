# ERP-009-001 登录与密码恢复体验优化

## 目标

- 登录、首次改密及管理员重置密码支持密码可见性切换。
- 密码策略统一为 6–128 位，且至少包含一个英文字母和一个数字。
- 用户可通过已绑定邮箱或手机号申请验证码并重置密码。

## 安全约束

- 找回密码申请始终返回统一结果，避免枚举账号。
- 验证码仅保存 BCrypt 哈希，10 分钟过期、最多尝试 5 次、成功后单次失效。
- 新验证码会使同一账号同一渠道的旧验证码失效；每小时最多申请 5 次。
- 重置成功后清除锁定状态并吊销该用户所有活动会话。
- 邮件与短信发送通过 `PasswordResetDelivery` 边界接入；未配置供应商时明确返回服务不可用，不伪造投递成功。

## 验收

- 后端覆盖密码格式、统一申请响应、过期/错误/单次验证码、限流、会话吊销及审计。
- 前端覆盖眼睛按钮、忘记密码两阶段流程、密码格式提示及 API 调用。
- Flyway V4 可从现有 V3 数据库无损升级。

## 验收结论

- 后端 `clean verify`：43 项测试通过。
- 前端 `pnpm quality`：13 个测试文件、41 项测试通过；lint、类型检查和生产构建通过。
- 临时 MySQL 8：V1–V4 迁移、数据库重启持久化及 mock 接口隔离通过。
- SMTP 和短信 webhook 均采用可配置投递边界；未配置时保持禁用并返回服务不可用，正式启用需另行注入供应商凭据并执行端到端投递验收。
