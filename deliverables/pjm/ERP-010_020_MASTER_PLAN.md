| 字段 | 内容 |
| --- | --- |

| 状态 | In Progress |

## 1. 执行规则

- 每个版本使用独立 `feature/ERP-xxx-*` 分支和原子提交。
- 每版必须通过受影响的后端、前端、导入契约、真实 MySQL 迁移、权限、审计和持久化门禁。
- 无法由工程侧消除的外部输入登记为待办，并继续后续无依赖版本；不得用合成数据冒充业务验收完成。
- 当前范围继续遵守 `MVP_ACTIVE_SCOPE_CONTRACT.md`，不引入 StoreListing、AmazonCatalogItem 或多店铺映射。

## 2. 版本范围与验收

### ERP-010：正式 Product / SKU 持久化

实现 Product、ProductVariant、VariantAttribute 的 MySQL 持久化、正式 API、产品新增/详情/编辑/停用页面。验收覆盖编码大小写不敏感唯一、变体组合唯一、逻辑停用、权限、审计和重启持久化。

### ERP-011：正式辅料主档

实现 AuxiliaryMaterial 的正式 API 与页面。验收覆盖编码唯一、字段校验、停用语义、权限、审计和重启持久化。

### ERP-012：SKU—辅料关系

实现 ProductAuxiliaryMaterial 和产品详情“对应辅料”，支持应用到全部 SKU。验收覆盖关系唯一、用量和损耗率校验、启用对象引用、批量应用及独立调整。

### ERP-013：单仓库存闭环

实现固定仓库、库存余额及不可变流水。验收覆盖余额重算、负库存保护、请求幂等、并发一致性、安全库存和事务原子性。

### ERP-014：五类导入批次底座

实现上传、全量校验、预览、确认、取消和结果下载状态机，仅允许当前五类资源。验收覆盖非法迁移、逐行错误、权限、审计和文件安全。

### ERP-015：产品与 SKU 导入

实现 PRODUCTS、VARIANTS 及动态属性导入。验收覆盖幂等 Upsert、引用/唯一/组合校验、整批事务及 1,000 行性能门禁。

### ERP-016：辅料与关系导入

实现 AUXILIARY_MATERIALS、PRODUCT_AUXILIARY_MATERIALS 导入。验收覆盖依赖顺序、编码引用、用量/单位/损耗率、整批事务和逐行结果。

### ERP-017：期初库存导入与导入收口

实现 AUXILIARY_MATERIAL_OPENING_INVENTORY，并完成五类导入 UI、批次详情和结果文件。验收覆盖零期初、同载荷幂等、异载荷拒绝、余额/流水/审计原子性。

### ERP-018：正式选品持久化

将候选、评估、状态、负责人、标签、评审、证据和 CSV 从 mock 迁至正式 MySQL。验收覆盖 ASIN/URL 查重、固定状态机、淘汰原因、追加语义、安全导出、权限和审计。

### ERP-019：正式 Watch 闭环

实现店铺、运行、快照、基线、新品事件、人工复核、候选来源和 CollectorAdapter。验收覆盖安全基线、坏快照保护、事件去重、候选单次生成、持久化和审计。

### ERP-020：集成硬化与试点候选版

完成端到端回归、性能、备份恢复、运行手册、浏览器验收和最终缺陷清单。验收目标：P0=0、普通列表 P95 不高于 2 秒、1,000 行导入不高于 5 分钟、三角色端到端和备份恢复演练通过。

## 4. 统一质量门禁

1. 后端：`./mvnw clean verify`。
2. 前端：`pnpm quality`。
3. 导入变更：机器契约测试与校验全部通过。
4. 真实临时 MySQL：迁移、重启持久化和 mock 隔离通过。
5. 权限、校验、失败、幂等与审计自动化测试通过。
6. `git diff --check`、工作树干净、本地与远端 SHA 一致。
