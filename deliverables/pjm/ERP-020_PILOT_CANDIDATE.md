# ERP-020 试点候选版集成加固

## 结论

ERP-010～ERP-019 的技术功能已串联为可复现验收的试点候选版。本文只记录工程验收；真实业务数据 UAT 尚未执行，不得据此宣称业务验收通过。

## 自动化证据

- 单命令门禁：`scripts/qa/verify-pilot-candidate.sh`
  - 后端 `clean verify`
  - 前端 `pnpm quality`
  - import-contract Node/Python 校验
  - MVP 活跃范围校验
  - 临时 MySQL V1→V13、重启持久化、mock 隔离
  - 实际 MySQL 备份恢复演练与轻量性能基线
- 备份恢复：`scripts/qa/verify-mysql-backup-restore.sh`
  - 使用临时 MySQL 8 和真实 V1→V13 schema
  - 实际执行压缩备份、清空目标库、恢复
  - 校验 Flyway 版本、关键表计数与探针数据
- 性能基线：`scripts/qa/verify-performance-baseline.sh`
  - 普通产品列表 200 行、30 次采样，P95 阈值 2 秒
  - 1000 行 PRODUCTS 导入、验证和提交阈值 5 分钟
  - 结果仅代表当前测试硬件，不外推生产容量
- staging：每天 03:30 清理超过默认 7 天的受控终态文件；任何活跃批次文件、符号链接和未知文件名均不删除。

## 关键安全与一致性约束

- 库存流水不可变；请求幂等；默认禁止负库存；期初每材料一次。
- 五类导入无部分成功，提交失败整批回滚；STORE_LISTINGS 保持拒绝。
- 导入文件路径受控，不保存客户端路径；凭据不入库、不进入脚本参数。
- 选品 notes/evidence 只追加，HTTPS 证据校验，CSV 公式注入防护。
- Watch 坏快照不覆盖基线，同店同 ASIN 不重复事件，单事件只关联一个候选。
- 未获 WATCH-001 授权时只有人工快照适配器，不实现或伪装自动抓取。

## 外部待办

1. **业务 UAT**：业务负责人提供真实、脱敏且获批的产品、辅料、库存、导入和选品样本并签字。
2. **WATCH-001**：批准公开店铺链接、采集规则、7 天指标来源及合规边界；批准前保持人工快照。
3. **RPO/RTO**：运维与业务确定目标、备份频率/保留、异地副本和演练周期。
4. **邮件/短信**：选择供应商，通过 Secret Store 配置并完成真实投递验收。
5. **容量与高可用**：在目标基础设施和预期并发下另行压测、容量规划与故障演练。
