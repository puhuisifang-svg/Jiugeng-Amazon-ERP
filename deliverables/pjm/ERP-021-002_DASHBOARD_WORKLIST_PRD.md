## 1. 背景与问题

当前首页主要展示模拟摘要，无法承载日常发货安排和新品开发待办。相关信息若继续分散在表格或即时通信中，容易出现遗漏、信息不同步和责任不清。

本迭代在首页增加“今日发货”“待发货”“新品待开发”三个页签，以持续滚动列表展示需要关注的数据；同时增加对应的维护菜单，使授权人员可以新增、修改、归档和推进记录。

## 2. 产品目标

1. 用户进入系统后可在首页快速看到当天发货、后续待发货和新品开发待办。
2. 数据超过可视区域时自动、连续滚动，无需用户频繁翻页。
3. 授权人员可通过独立菜单维护首页数据，维护结果及时反映到首页。
4. 数据变更可校验、可追溯、可审计，不通过物理删除掩盖历史。

## 3. 范围

### 3.1 本期包含

- 首页三个页签及数量徽标。
- 三类数据的滚动列表、空状态、加载状态、失败状态和超期提示。
- “今日发货管理”“待发货管理”“新品待开发管理”三个菜单和维护页面。
- 新增、编辑、归档、历史查看及业务状态推进。
- 待发货记录人工转入今日发货。
- 新品开发记录标记完成。
- 产品目录关联、图片上传或选择、权限控制和操作审计。

### 3.2 本期不包含

- 物流承运商、运单号、运输轨迹和签收管理。
- 采购、生产排期、生产工单和成品库存扣减。
- 自动读取 Amazon 订单或第三方 ERP 发货数据。
- Excel 批量导入、消息推送、邮件提醒和移动端页面。
- 新品开发审批流、成本核算和任务分派。

## 4. 用户与权限

建议新增两个能力点，避免复用产品或库存权限造成权限含义混乱：

| Capability | 管理员 | 产品/辅料人员 | 选品人员 |
| --- | --- | --- | --- |
| `dashboard.read` | 是 | 是 | 是 |
| `dashboard.manage` | 是 | 是 | 否 |

- 所有已登录用户均可查看首页三个页签。
- 管理员和产品/辅料人员可进入三个维护菜单并执行维护操作。
- 选品人员仅可查看首页，不显示维护菜单，后端接口仍需独立拒绝越权请求。
- 新增、编辑、归档、转入今日发货、标记完成等操作必须记录审计事件。

> 评审项：新品开发是否需要开放给选品人员维护。推荐首版只允许管理员和产品/辅料人员维护，待流程明确后再扩权。

## 5. 信息架构与菜单

```text
工作台
├── 首页
│   ├── 今日发货
│   ├── 待发货
│   └── 新品待开发
└── 工作台维护
    ├── 今日发货管理
    ├── 待发货管理
    └── 新品待开发管理
```

菜单要求：

- 首页仍为登录后的默认页面。
- 三个维护菜单归入新增的“工作台维护”菜单组。
- 无 `dashboard.manage` 权限时隐藏整个“工作台维护”菜单组。
- 维护页面支持通过返回入口回到首页对应页签。

## 6. 首页交互需求

### 6.1 页签规则

- 页签顺序固定为：今日发货、待发货、新品待开发。
- 默认选中“今日发货”。
- 每个页签显示当前有效记录数量，例如“待发货 12”。
- 用户切换页签后，从列表顶部开始展示并重新计算滚动。
- 页面重新获得焦点或维护成功后刷新数据；常规展示期间每 60 秒静默刷新一次。

### 6.2 滚动列表规则

- 列表区域使用固定可视高度，建议桌面端展示 6～8 行。
- 记录未超过可视区域时静态展示，不启动滚动。
- 记录超过可视区域时纵向连续循环滚动，首尾衔接不得出现明显空白或跳动。
- 默认速度建议为每秒 20～30 像素，由 UI 验收时确定最终值。
- 鼠标移入、键盘焦点进入或用户手动滚动时立即暂停；鼠标离开或焦点移出 3 秒后继续。
- 用户切换浏览器标签页时暂停，返回后继续。
- 系统启用“减少动态效果”时关闭自动滚动，改为用户手动滚动。
- 不得因自动刷新把用户正在查看的详情、焦点或手动滚动位置强制重置。

### 6.3 排序和强调

- 今日发货：按最晚发货时间升序，再按产品编号升序；已超过最晚发货时间的记录以红色“已超时”标识。
- 待发货：按计划发货日期升序、最晚发货时间升序、产品编号升序；计划日期早于当前日期的记录标识“已逾期”。
- 新品待开发：按预计完成时间升序，再按创建时间升序；预计完成时间早于当前日期的记录标识“已逾期”。
- 所有日期和时间按 `Asia/Shanghai` 展示。

### 6.4 首页数据范围

- 今日发货只展示状态为“有效”且发货日期等于当前业务日期的记录；历史记录在维护页面查询。
- 待发货展示所有尚未转入今日发货或归档的有效记录，包括已逾期记录。
- 新品待开发只展示状态为“待开发”的记录；已完成和已归档记录只在维护页面查询。

### 7.4 系统字段

三类记录均需保存以下不直接作为首页业务列展示的系统字段：

- 记录 ID。
- 业务状态。
- 创建人、创建时间、最后修改人、最后修改时间。
- 归档人、归档时间及归档原因。
- 乐观锁版本号，防止多人编辑时后保存覆盖先保存。

## 8. 产品图案要求

本 PRD 暂按“产品图案是图片”设计：

- 支持 JPG、PNG、WebP。
- 单文件建议不超过 5 MB。
- 服务端校验真实文件类型，不仅检查扩展名。
- 列表使用缩略图，原图使用受控文件地址访问。
- 替换图片后保留操作审计；归档业务记录不得立即删除仍被引用的图片。
- 不允许前端直接保存任意外部图片 URL，避免失效链接和不受控内容。

> 评审项：确认“产品图案”是上传图片、图案编号还是文本描述。若实际为图案编号，应删除文件上传范围并将字段改为最长 128 字符的文本。

## 9. 维护页面需求

### 9.1 通用能力

- 列表支持关键字、状态和日期范围筛选。
- 支持新增、编辑、查看详情、归档和查看历史记录。
- 默认只显示有效记录，可切换查看已完成或已归档记录。
- 不提供物理删除按钮；错误记录通过归档处理并填写原因。
- 新增和编辑使用明确的保存、取消按钮，离开未保存页面时提示用户。
- 保存成功后立即刷新维护列表和首页对应页签。
- API 失败时保留用户已填写内容，并显示可操作的错误提示。

### 9.2 今日发货管理

- 可新增和编辑今日或历史发货记录。
- 默认筛选当前日期。
- 支持按发货日期、产品编号、产品名称和是否超时筛选。
- 历史记录只允许查看或归档；如需更正，授权人员可编辑但必须记录前后值和更正原因。

### 9.3 待发货管理

- 支持按计划发货日期、产品编号、产品名称和逾期状态筛选。
- 提供“转入今日发货”操作：
  1. 用户确认实际发货日期、数量、箱数、备注和最晚发货时间。
  2. 系统在同一事务中创建今日发货记录，并将原待发货记录标记为“已转入”。
  3. 重复提交不得生成第二条今日发货记录。
  4. 转入操作需记录来源关系和审计事件。
- 计划日期到达当天时不自动转入，避免未经确认产生发货事实。

### 9.4 新品待开发管理

- 支持按产品名称、预计完成时间、状态和逾期状态筛选。
- 状态至少包含：待开发、已完成、已归档。
- 提供“标记完成”操作；完成后记录完成人和完成时间，并从首页滚动列表移除。
- 本期不自动创建 Product；如后续需要，可单独设计“转为正式产品”流程。

## 10. 状态与数据一致性

### 10.1 今日发货

`ACTIVE → ARCHIVED`

### 10.2 待发货

- `PENDING → TRANSFERRED_TO_TODAY`
- `PENDING → ARCHIVED`

### 10.3 新品待开发

- `PENDING → COMPLETED`
- `PENDING → ARCHIVED`

要求：

- 非法状态迁移由后端拒绝。
- 转入今日发货采用事务和幂等键保证原子性与单次生成。
- 已归档记录不得重新出现在首页；如需要恢复，应提供单独的“恢复”操作并记录原因。
- 图片上传失败时不得创建业务记录；业务记录保存失败时应清理未被引用的临时文件。

## 11. 接口范围建议

接口名称可在技术设计阶段调整，但资源边界应保持清晰：

```text
GET    /api/v1/dashboard/today-shipments
GET    /api/v1/dashboard/pending-shipments
GET    /api/v1/dashboard/pending-products

GET    /api/v1/dashboard-maintenance/today-shipments
POST   /api/v1/dashboard-maintenance/today-shipments
PATCH  /api/v1/dashboard-maintenance/today-shipments/{id}
POST   /api/v1/dashboard-maintenance/today-shipments/{id}/archive

GET    /api/v1/dashboard-maintenance/pending-shipments
POST   /api/v1/dashboard-maintenance/pending-shipments
PATCH  /api/v1/dashboard-maintenance/pending-shipments/{id}
POST   /api/v1/dashboard-maintenance/pending-shipments/{id}/transfer-to-today
POST   /api/v1/dashboard-maintenance/pending-shipments/{id}/archive

GET    /api/v1/dashboard-maintenance/pending-products
POST   /api/v1/dashboard-maintenance/pending-products
PATCH  /api/v1/dashboard-maintenance/pending-products/{id}
POST   /api/v1/dashboard-maintenance/pending-products/{id}/complete
POST   /api/v1/dashboard-maintenance/pending-products/{id}/archive
```

- 首页读取接口返回已排序的轻量列表。
- 维护接口采用分页查询，默认每页 20 条，最大每页 100 条。
- 所有写接口校验 `dashboard.manage`，并接入统一审计。
- 图片上传使用独立、受控的文件接口，技术设计阶段确定具体路径和存储实现。

## 12. 空、加载和错误状态

- 加载中：显示列表骨架，不显示旧数量为 0 的误导状态。
- 空数据：分别显示“今日暂无发货安排”“暂无待发货记录”“暂无待开发新品”。
- 单个图片加载失败：显示统一占位图，不阻塞整行数据展示。
- 列表接口失败：保留上次成功数据时标记“数据可能不是最新”；无缓存时显示重试按钮。
- 维护保存冲突：提示“记录已被其他用户更新”，要求重新加载后再提交。
- 无权限：菜单隐藏，直接访问路由返回 403 页面，后端返回结构化权限错误。

## 13. 非功能要求

- 首页三个列表接口在正常数据规模下 P95 不高于 2 秒。
- 滚动动画在支持的桌面浏览器中保持流畅，不得导致页面明显卡顿或持续高 CPU 占用。
- 首页单次返回记录建议不超过 200 条；超过时显示“仅展示前 200 条，前往维护页查看全部”。具体上限由技术评审确认。
- 图片列表使用缩略图和延迟加载，不直接加载原图。
- 支持最新版 Chrome 和 Edge，桌面宽度低于 1280 像素时允许表格横向滚动。
- 写操作审计覆盖率 100%，审计快照不得包含文件二进制内容。
- 数据库迁移必须兼容当前 MySQL 8 和自动化测试使用的 H2。

## 14. 验收标准

### AC-01 首页页签

- 登录后首页按固定顺序显示三个页签及准确数量。
- 每个页签的字段、排序、空状态和超期样式符合本 PRD。

### AC-02 持续滚动

- 不超过可视行数时列表不滚动。
- 超过可视行数时列表连续循环滚动，无明显空白和跳动。
- 鼠标、键盘焦点、页面隐藏和减少动态效果规则生效。

### AC-03 数据维护

- 授权人员可新增、编辑、归档三类数据。
- 保存后首页在刷新周期内展示最新数据。
- 非法数量、箱数、日期时间、图片或超长文本被前后端共同拒绝。

### AC-04 待发货转入

- 转入操作同时生成今日发货记录并关闭原待发货记录。
- 请求失败时两边均不产生部分结果；重复请求不重复生成。

### AC-05 新品完成

- 标记完成后记录完成人和完成时间，并从首页移除。
- 已完成记录可在维护页面查询。

### AC-06 权限与审计

- 无维护权限的角色看不到维护菜单，直接调用写接口返回 403。
- 所有写操作记录操作人、时间、动作、资源和脱敏前后值。
- 普通用户不能修改或删除审计记录。

### AC-07 持久化与质量

- MySQL 重启后业务记录、状态和图片引用保持不变。
- 后端、前端、数据库迁移、权限、审计、并发冲突和滚动交互测试通过。
- `git diff --check` 及敏感信息检查通过。

## 15. 评审决策项

| ID | 决策项 | 推荐方案 | 不确认的影响 |
| --- | --- | --- | --- |
| D-021-002-01 | “产品图案”的实际含义 | 图片上传并显示缩略图 | 无法冻结字段类型、文件存储和 UI |
| D-021-002-02 | 今日发货表示计划还是已确认发货 | 表示经人工确认转入的当日发货安排 | 影响状态和待发货转入逻辑 |
| D-021-002-03 | 选品人员是否可维护新品待开发 | 首版只读 | 影响 capability 和菜单 |
| D-021-002-04 | 发货数量的计量单位 | 首版按件，页面明确显示“件” | 影响字段文案和校验 |
| D-021-002-05 | 新品待开发的“发货数量”是否应改为“预计数量” | 保留原字段，评审时确认文案 | 影响业务理解和历史数据 |
| D-021-002-06 | 图片存储位置 | 复用受控本地文件存储抽象，预留对象存储实现 | 影响技术方案和备份范围 |
| D-021-002-07 | 首页最大滚动记录数 | 200 条，超出引导至维护页 | 影响接口和前端性能 |

## 16. 建议拆分

评审通过后建议按以下子任务实施：

1. `ERP-021-002-01`：数据模型、迁移、权限和审计边界。
