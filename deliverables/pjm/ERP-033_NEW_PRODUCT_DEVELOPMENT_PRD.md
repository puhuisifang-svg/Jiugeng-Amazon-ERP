# ERP-033 新品开发 PRD v1.0

状态：2026-10-16 用户授权编写 PRD 并自主实施；PJM 分配 ERP-033 及独占开发/部署窗口。基线 main `433e5581d46ac3a57cf1102a9844a20c5ed05a67`，分支 `feature/ERP-033-new-product-development`。

## 1. 目标与参考

在“商品 / 产品管理”分组下新增“新品开发”入口，将选品通过后的研究成果转成可持续跟进的开发需求。保留现有产品管理、采购与监控功能，不修改用户历史资料。

已只读查看用户打开的[赛狐新品开发](https://www.sellfox.com/amzup-web-main/web/productInvent/index.html)列表与新增需求表单，未保存或提交赛狐数据。观察到：全部/草稿/进行中/已完成/已作废、站点/人员/推荐星级/开发时间筛选、需求名称/开发人员/采购员/开发周期、商品信息、供应商、竞品研究与利润试算。本系统借鉴需求管理结构，沿用现有 UI，不复制第三方资产或宣称实现未接入的外部服务。

## 2. 候选联动（P0 核心）

- 候选 `REVIEWING → APPROVED` 时，在同一事务内自动生成新品开发草稿；创建失败则审核通过整体回滚，不出现通过但丢失开发需求的状态。
- 一候选一开发需求，数据库唯一约束兜底；重复审核不能生成重复单据。来源候选 ID、ASIN、标题、类目、评分、参考价格、选品理由保存为审批时快照，后续候选评估编辑不覆盖开发资料。
- 已通过的历史候选由增量迁移补建草稿；待审核/淘汰候选不进入开发。迁移不改变原候选状态和追加式评审/证据。
- 候选池卡片与详情显示“进入新品开发”，未通过不显示；页面按候选 ID 直接定位对应需求。新品开发详情提供返回来源候选与标准 Amazon 链接。
- 不把候选的竞品 ASIN 当作自有 SKU，不把竞品售价当采购成本，不自动创建商品或采购单。

## 3. 页面与字段

### 列表

入口“商品 / 产品管理 / 新品开发”，路径 `/product-development`。状态标签、关键词（需求编号/名称/ASIN/开发员）、分页 20/50/100、刷新与空态引导到候选池。服务器分页，避免一次拉取所有开发资料。

显示需求编号、名称、来源 ASIN、开发员、推荐星级、开发周期、状态、更新时间。编号 `ND-<ASIN>`；站点首期美国，继承现有候选池站点边界。

### 详情

- 来源信息只读：候选快照、参考售价（仅参考）、来源链接、选品理由、候选记录入口。
- 基本信息：需求名称必填（300 字）、开发员/采购员（各 100 字）、推荐星级（0=未评定，1–5）、开发开始/结束日期、预计开售日期、备注（3000 字）。
- 商品方案：计划品名（300 字）、品牌/类目（100 字）、计划 SKU（100 字，仅方案）、材质（200 字）、采购成本 CNY、重量 g、长宽高 cm（非负且最多 4 位小数；上限 9999999999.9999）。空值为未知，0 不代表未知。
- 供应与研究：供货方案/报价说明、打样与验收记录、竞品研究结论（各 3000 字，文本；不自动抓取外站、不触发采购）。复用候选详情查看原始证据。
- 开发成果：完成时必须关联一个已启用的现有产品，调用产品模块公共查询边界校验。未建档时引导去产品管理建立档案，再回填关联；不自动把竞品复制为自有产品。
- 操作历史只追加，记录创建、保存、开始、完成与作废；敏感自由文本/URL 不写入审计快照。

## 4. 状态、权限与异常

`DRAFT → IN_PROGRESS → COMPLETED`；DRAFT/IN_PROGRESS 可作废，作废原因必填；COMPLETED/VOID 只读，无物理删除或恢复按钮。

- 开始开发需填写开发员、计划品名与完整有效开发周期；结束日不能早于开始日，开售日不能早于结束日。
- 完成需关联启用产品并填写打样/验收结论；关联操作只保存在本需求，不修改产品档案。
- 修改与状态转换必须提交 version；并发冲突返回 409，保留输入并提示刷新，不覆盖他人数据。
- 复用 `products.read`（三角色可读）和 `products.write`（管理员/产品辅料可维护）；选品角色可审批候选并查看开发结果，不额外获得产品写权限。
- mock 模式不提供真实新品开发 API；候选联动入口仅用于正式持久化模式。正式候选页面不得无条件展示 SYNTHETIC 标识。

## 5. API 与架构

`GET /api/v1/product-development?status=&q=&page=0&size=20` 返回 items/total/page/size；`GET /{candidateId}` 返回需求+历史；`PUT /{candidateId}` 保存草稿/进行中资料；`POST /{candidateId}/transition` 携带 version、target、reason。

使用独立 development 模块。selection 仅发布公共 CandidateApproved 领域事件，不依赖 development 内部类型；development 使用同步事件监听参与审批事务，依赖 product 的公共 ProductLookup。新增 V25 表与历史通过数据回填，保持模块无环和数据可恢复。

## 6. 范围外

首期不含独立手工建需求、导入/复制/删除、自定义字段引擎、1688/AI 自动调研、利润核算、自动报价、上传附件、复杂多属性 SKU 编辑、多级审批和自动创建商品。通过现有候选评审及商品管理承接，不提供空按钮。
