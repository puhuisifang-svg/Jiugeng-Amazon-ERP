# ERP-034 手动添加新品需求

2026-10-16 用户明确要求新增“添加新品需求”并开发部署。PJM 授权独占写入、提交、测试、备份与部署窗口，并批准以 ERP-033 `fe8a578a3173ca8aca52a915ba1072903170094f` 为例外基线；分支 `feature/ERP-034-manual-product-development`。ERP-033/034 后续由 PJM 统一复核线性合并，当前不由 Codex 合并 main。

## 增量范围（覆盖 ERP-033 PRD 的仅候选来源限制）

- 商品 / 产品管理 / 新品开发列表新增“添加新品需求”，仅 products.write（ADMIN、PRODUCT_MATERIAL）且正式模式可用；SELECTION 仍可读不可手动创建。
- 路由 `/product-development/new`，复用现有完整资料表单。需求名称必填，其余允许稍后完善。保存创建 DRAFT 并进入详情；未保存离开提示，校验/网络错误保留输入。
- 来源分为 CANDIDATE / MANUAL，列表和详情清晰展示。手动需求不要求 ASIN、候选 ID、Amazon 链接、参考售价或选品分数，不伪造候选快照、不创建候选。候选审批链路和历史数据保持不变。
- 手动编号由数据库锁保护的序列产生，格式 `ND-M-00000001` 起，不由客户端决定。允许不同真实需求重名；防双击和网络重试通过 requestId+请求内容哈希+创建者校验，同一请求只创建一次、审计一次；不同内容复用请求号返回 409。
- `POST /api/v1/product-development` 接受 requestId（UUID）和 fields；使用 products.write。来源固定 MANUAL，不接受客户端伪造候选/完成状态。已创建的来源不可编辑。
- 复用既有字段、版本校验、进行中/完成/作废约束、打样与启用产品完成条件和追加审计；不新增手动完成捷径，不改采购/库存。
- V26 增量迁移使候选快照可空，增加来源类型、手动创建幂等元数据与编号锁；历史行默认为 CANDIDATE。数据库约束要求来源与候选/手动请求一致。

## 实施与验收

1. 后端迁移、创建接口与服务；候选路径兼容，审计允许无候选来源。
2. 前端新建路由/入口、复用表单、来源展示、失败保留与重复提交保护。
3. 测试三角色/匿名、新建校验、同请求并发/重放/跨用户冲突、候选回归、迁移、无来源链接、完整状态流转。
4. 后端 clean verify、前端 pnpm quality、scope validator、MySQL HTTP/重启、备份恢复和 diff check；正式环境停写备份后重启后端，公网及浏览器合成数据验收并清理。

无新增外部采集、附件、自动建商品或采购单。既有美国站候选范围不变；手动需求为内部开发计划，不据此宣称已支持 Amazon 多站点集成。
