## 冻结需求

- 订单/订单管理/客户订单：手工录入 1688 或线下订单；一个客户、多商品 SKU 明细。
- 客户商品、品名与名称格式快照、规格型号、数量（最多3位小数）、单位、不含税单价（最多6位）、税率（默认1%）、净额/税额/含税总价。
- 下单日期、交期、合同号、客户订单号、收货人/手机号/地址、备注；客户抬头唯一时自动带出、多抬头手工选择。
- 草稿、确认、完成、取消、关闭；独立显示发货与开票进度，确认操作有防误触与审计。
- 订单支持多商品分批安排待发货，关联今日发货与发货统计；防重复、防超量，往返转换不重复占用，删除未完成安排释放数量。
- 一个订单唯一一张多商品发票；发票仅管理抬头、商品金额、开票状态、号码日期附件及来源订单链接，不管理或展示发货/物流。
- 旧手工发票数据保留，界面移除发货/物流字段；旧无订单发货继续可用。
- 订单/发货维护物流，发票不承担该职责。快照不随主档修改而改写。
- 不接1688、税务或物流外部接口，不涉及收款、库存扣减、退货或红冲。

## 实施顺序

1. 数据迁移、订单与多商品发票领域、金额与快照、权限和状态校验。
2. 发货公开边界、分批占用/释放/完成、数量精度和单位、订单关联及历史兼容。
3. 前端订单列表/详情/表单、发票内容界面及发货关联入口，遵循 UI_STANDARD。
4. 隔离回归测试、前后端全门禁、浏览器验证、检查差异后本地提交并交接。

## 实现与交接范围

- 后端 `customer/CustomerOrder*`：订单查询、草稿编辑/确认/取消/关闭、按行金额核算、客户商品/抬头/名称样式快照、内容变更审计、一单一张多商品发票、开票后财务字段锁定。
- `customer/OrderFulfillment*`、`dashboard/OrderShipment*`：同事务分批占用、可用量校验、删除释放、待发货/今日发货往返、发货完成、订单批次物流；更新箱数、日期、数量和备注同步订单。并发写入采用订单行锁与 READ_COMMITTED，重复请求采用幂等键。
- `customer/OrderDocumentController`：订单/发票附件权限、归属、10MB限制、扩展名与文件签名检查；复用私有对象存储及现有数据库回退机制。
- V42/V43：新增订单、明细、安排、唯一发票和附件表；旧发货整数改为小数时保留历史 INT 全范围，旧单位 SET 和无订单关联的数据不改写。
- 前端新增 `api/orders.ts`、`CustomerOrderEditor`、`CustomerOrdersView`、`OrderInvoicesView`、`OrderDocuments`；菜单与面包屑、新增/编辑、分批安排、开票、附件、中文字段变更说明。历史手工发票入口保留，但界面不再显示/编辑发货或物流。
- 现有首页/发货管理/统计/图片导出支持订单单位与小数；来源订单跳转和筛选；外箱标合同号默认带出订单合同号（无合同时取客户订单号），仍支持手工修改。
- UI 规范新增订单弹窗、表格、发票职责和数量汇总规范。首版未引入新依赖。
