## 1. 目标

在 Sprint 0 先完成静态评审与可执行的验收设计；待 PM、UI、Backend、Frontend、Ops 交付后，验证字段与模板契约、编码规则、三角色可见性、导入错误定位、监控快照保护与新品去重、工程干净构建、Compose 持久化、CI 和敏感信息扫描。测试结论必须可由交付路径、命令输出、API/数据库核对或截图复现。

## 2. 测试基线与优先级

1. `Approved` 文档优先：MVP 最终规划 v1.0、PRD v1.0、权限矩阵 v1.0、验收标准 v1.0、产品数据模型 v1.0、编码规则 v1.0、架构 v1.0。
2. Sprint 0 执行以 Sprint 计划、任务看板及已批准变更为准。
3. Draft 文档只作辅助，不得覆盖 Approved 基线；发现冲突先登记，由 PJM/Owner 决策后再验收。
4. 本轮不验收正式业务功能、生产迁移、5 店 SP-API 自动同步或任何绕过平台访问控制的采集方式。

## 3. 阶段、入口与退出

### 3.1 阶段 A：静态评审与测试设计（本次）

- 输入：Sprint 0 计划、PRD、权限矩阵、验收标准、测试策略及相关 Approved 设计。
- 输出：本计划、需求追踪矩阵、验收清单、静态问题清单。
- 完成条件：所有 S0-QA-01 指定范围均有测试 ID、预期结果、责任交付和证据要求。

### 3.2 阶段 B：交付验收（各 Owner 交付后）

入口条件：

- PM 提供字段字典、字段 Owner、6 类模板、合法/非法样例及业务输入状态。
- UI 提供三角色流程及正常、空、错、无权、导入中/失败状态。
- Backend/Frontend 提供固定依赖版本、锁文件/Wrapper、测试命令与自测证据。
- Ops 提供 Compose、非敏感配置样例、健康检查、持久化说明及 CI 定义。
- Spike 提供 3 店原快照证据、完整性判定、每日任务记录细与 Stage Gate 报告。

退出条件：

- 追踪矩阵 P0 覆盖率 100%，验收清单所有必验项有结论和证据。
- P0 缺陷为 0；P1 无未批准遗留；所有阻塞项有 Owner、期限和批准记录。
- 前后端干净安装、测试和构建通过；Compose 重建后持久数据保留。
- CI 的构建、测试和敏感扫描在目标分支可重复运行且通过。
- 监控从首个完整有效快照开始计时，完成连续 7 天或按批准的人工导入降级范围验收。

## 4. 测试对象与方法

| 专项 | 主要方法 | 核心判定 |
| --- | --- | --- |
| 字段/模板 | 规格走查、表头机器比对、样例导入、跨层抽样 | 字段名、类型、必填、枚举、唯一/引用、Owner、示例在字典/模板/UI/API/DB 一致 |
| 编码 | 等价类、边界值、大小写/空白变形、并发重复 | 手工输入；1～64 位；合法字符；trim；大小写不敏感唯一；界面/导入同规则 |
| 三角色 | 菜单检查 + API 直接越权矩阵 | 前端无权能力不可见；后端无权请求 100% 拦截；审计范围正确 |
| 导入 | 正反例、混合批次、跨表引用、错误报告核对 | 上传→校验→预览不落库；错误精确到工作表/行/字段/原因；无静默丢数 |
| 监控 | 快照状态机、故障注入、集合差异、重跑/并发 | 仅完整成功快照提升基线；失败/空/分页不全不污染；店铺+ASIN 去重 |
| 工程 | 全新临时目录/无缓存构建 | 锁文件/Wrapper 生效，lint/test/build 可重复通过，无隐藏本机依赖 |
| Compose | 健康检查、写入-重启-重建-读取 | MySQL/Redis/对象存储健康；声明的数据卷重建后数据仍在 |
| CI/安全 | PR/分支触发、故意失败验证、仓库历史与产物扫描 | 构建/测试/扫描真实执行；失败能阻断；无真实凭据，日志不泄密 |

## 5. 测试数据

- **业务样本集**：20～50 条脱敏产品/SKU/辅料关系/期初库存数据，包含 5 店映射。
- **编码边界集**：长度 1、64、65；字母/数字/`-`/`_`；中文、空格、特殊字符；首尾空格；仅大小写不同；跨批次与并发重复。
- **导入错误集**：缺表/错表头、缺必填、非法枚举、重复键、大小写重复、引用不存在、父子店铺不一致、部分合法部分非法、公式/空行/超长值。
- **角色账号集**：系统管理员、产品/辅料人员、选品人员各 1 个；另含停用/锁定账号。不得在仓库记录密码或会话值。
- **监控快照集**：完整基线 A；新增 ASIN 的完整快照 B；完全相同的重跑 B2；失败、空结果、分页不完整、重复 ASIN、跨店同 ASIN、乱序页面样本。
- **持久化探针**：MySQL 测试行、Redis 非关键探针、对象存储测试对象；仅使用伪造/脱敏内容。
- **敏感扫描种子**：只使用扫描器官方测试标记或明确无效的伪造值，禁止使用真实 Token、Key、密码或私钥。

## 6. 关键用例集

详细追踪见 `S0_QA_REQUIREMENTS_TRACEABILITY_MATRIX.md`；执行勾选见 `S0_QA_ACCEPTANCE_CHECKLIST.md`。

- `FLD-001～005`：七业务域字段覆盖、字段 Owner、六模板契约、5 店字段隔离、跨层一致性。
- `COD-001～007`：手工输入、长度/字符、trim、大小写唯一、停用不复用、修改权限与审计、UI/导入一致。
- `RBAC-001～009`：三角色菜单和 API 矩阵、库存隔离、审计范围、无权直链/直接 API、凭据值不可见。
- `IMP-001～008`：校验预览不落库、错误四要素、混合批次、引用/唯一约束、幂等 Upsert、无静默丢数、结果可下载、1,000 行性能预留。
- `WAT-001～009`：首次基线、有效快照完整性、失败/空/分页不全保护、差异识别、同店去重、跨店隔离、重跑并发、原始证据和任务可追踪。
- `BLD-001～004`：前端 pnpm 干净安装/lint/test/build；后端 Wrapper 干净 test/package；固定版本；无额外锁文件或本机依赖。
- `CMP-001～005`：服务定义、健康、迁移、重启/重建持久化、非敏感配置和故障可诊断。
- `CI-001～006`：触发器、前后端任务、敏感扫描、失败阻断、最小权限、日志/产物不含敏感值。

## 7. 执行与证据规范

每次执行记录：构建/提交标识、环境、操作者、时间、测试 ID、前置数据、实际结果、结论、缺陷 ID。证据按 `deliverables/qa/evidence/sprint-00/<build>/<test-id>/` 归档，建议包含：

- `commands.txt`：已脱敏命令及退出码；
- `result.txt` 或 JUnit/覆盖率/扫描报告；
- API 请求结构和已脱敏响应；
- 数据库核对 SQL 与结果摘要；
- 必要截图；
- 快照 hash、完整性状态、基线版本和任务 ID。

不得把凭据、Cookie、会话令牌、生产数据或敏感原始响应放入证据。验收报告只引用证据，不用口头结论替代。

## 8. 缺陷等级与上报

| 等级 | 判定示例 | 处理 |
| --- | --- | --- |
| P0 | 数据破坏/越权读取写入/真实凭据泄露；失败快照覆盖有效基线；主分支无法构建且无替代；Sprint 退出核心链路完全阻断 | 立即停止相关验收并向 PJM 报告；清零或由老板明确批准降级 |
| P1 | 核心规则错误、导入静默丢数、同店新品重复、持久化丢失、CI 未实际阻断、基线文档冲突影响实现 | 当日登记并指定 Owner；未批准不得遗留 |
| P2 | 非核心异常、文案/布局或证据完整性问题，不影响数据和核心门禁 | 纳入修复与回归计划 |

## 10. 已知依赖与风险

- 脱敏样本、3 个公开店铺链接、首期用户清单、GitHub 安全授权和可用镜像链路仍可能阻塞对应验收。

- Redis 仅存可重建状态；持久化重点是 MySQL 和对象存储，Redis 是否持久须由 Ops 配置说明决定并按声明验证。
- 若数据源 Stage Gate 决定人工导入，按批准的降级范围验收，不宣称自动监控已通过。
