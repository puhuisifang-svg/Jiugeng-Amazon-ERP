# 文档治理规范

## 1. 文档元数据

正式文档首页至少包含：项目名、文档名、Owner、版本、状态、更新时间、审批人。

## 2. 状态

- `Draft`：编写中，不作为执行依据。
- `In Review`：已提交评审，等待意见或批准。
- `Approved`：已批准，是当前执行基线。
- `Superseded`：已被新版本替代，仅用于追溯。
- `Active`：持续维护的台账类文档。

## 3. 版本规则

- `v0.x`：立项前草案。
- `v1.0`：首次批准版本。
- `v1.x`：不改变主要范围的增量修订。
- `v2.0`：范围、架构或流程发生重大变更。

## 4. 命名规则

- 文件使用大写英文和下划线，如 `TEST_REPORT.md`。
- Sprint 目录使用 `SPRINT-00`、`SPRINT-01`。
- 交付物建议使用 `YYYYMMDD_主题_v版本.md`。
- 图片放在文档同级 `assets/`，禁止散落在项目根目录。

## 5. 审批与变更

1. Owner 完成草稿并自检。
2. 相关角色评审并记录意见。
3. PJM 核对交付物、依赖和验收证据。
4. 需要老板确认的基线由老板批准。
5. 变更批准后同步更新文档、决策日志、Backlog 和交付物总账。

## 6. 禁止事项

- 禁止在项目文档中记录真实 Token、Key、密码、私钥、Cookie 或刷新令牌。
- 禁止用聊天结论代替正式决策记录。
- 禁止覆盖已批准版本且不保留变更说明。
- 禁止交付只有“已完成”结论、没有文件、测试、截图、日志或演示证据的成果。
