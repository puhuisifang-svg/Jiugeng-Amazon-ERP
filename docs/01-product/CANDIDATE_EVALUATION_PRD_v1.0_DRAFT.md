# 候选池：新品开发前评估 PRD v1.0

- 日期：2026-10-29
- 状态：用户认可本版作为设计基础；与新品开发联动PRD一并评审。本轮仅设计，不实施、不部署、不提交 main。
- 配套：[新品开发与候选评估联动 PRD](NEW_PRODUCT_DEVELOPMENT_LINKED_PRD_v1.0_DRAFT.md)。开发阶段、打样验收、方案变更及完成交接以配套PRD为准；新手动开发项目新增立项审批，明确覆盖旧的直接开始开发规则。
- 目标：将候选池从商品登记列表升级为新品立项评估工作台，回答“服务谁、解决什么问题、做哪些改进、预计能否盈利、是否值得投入开发”。
- 依据：用户本轮需求；现有候选池、选品研究、利润试算及新品开发代码；`docs/ui/UI_STANDARD.md`；ERP-033、ERP-034 与选品总 PRD。本文为九更业务设计，不宣称本轮已观察第三方页面或已接入新的数据源。
- 取代范围：批准实施后，本文覆盖旧 PRD 中候选池的来源限制、评估页布局、状态及审核规则；监控采集和新品开发执行流程保持各自边界。

## 1. 产品定位与边界

候选池管理“准备投入开发的产品机会”。竞品商品是分析依据，拟开发商品是决策对象，二者不能混为一份不断被采集覆盖的资料。

**业务链路：发现机会 → 建立候选 → 收集证据 → 形成产品方案 → 成本试算 → 提交审核 → 通过并生成新品开发草稿 → 开发执行。**

候选可以源自已有热销产品、近期发现的新品、供应商样品或原创概念；“候选新品”指我方拟开发新品，不要求来源商品在最近60天上架。上新监控的60天新品识别规则不作为候选入池门槛。

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 产品监控/上新监控 | 发现商品、保存前台观测及变化、提供候选入口 | 决定是否开发 |
| 候选池 | 研究客户需求、明确改进方案、测算经济性、形成审核决策 | 实际打样执行、采购、创建库存 |
| 新品开发 | 承接批准方案，分配开发与采购人员，打样、验收、关联自有商品 | 重复审批同一份选品结论 |

首期提供结构化人工评估、现有采集数据引用和系统试算。不把 AI 自动研究、第三方销量估算或自动评论抓取作为闭环前提。

## 2. 用户与权限

| 能力 | 查看人员 | 评估人员 | 审核人员 |
| --- | --- | --- | --- |
| 查看候选及授权范围内资料 | ✓ | ✓ | ✓ |
| 创建候选、补充证据 | — | ✓ | ✓ |
| 编辑评估及成本、提交审核 | — | ✓ | ✓ |
| 退回补充、通过、淘汰 | — | — | ✓ |
| 修改已提交版本 | — | — | — |

建议将评估编辑与审核分为独立权限，映射现有角色体系，默认管理员审核、选品人员评估；不让旧 `selection.write` 自动获得新的审批权限。上线前确认人员映射。审核记录显示提交人与审核人；首期不强制不同人，但自审须二次确认并留痕。新品开发的编辑权限继续由商品模块控制，通过候选不会自动授予开发权限。

## 3. 候选建立与来源

### 3.1 四种入口

| 来源 | 操作与必要输入 | 系统带入 | 异常处理 |
| --- | --- | --- | --- |
| 产品监控 | 行内/批量“加入候选”；填写负责人、候选理由 | 站点、ASIN、图片、标题、最新成功观测及原监控关联 | 已存在则打开/关联原候选，不覆盖评估 |
| 上新监控 | 店铺详情在线产品、上架记录、新品记录均可加入 | 上述商品信息、店铺、来源记录、首次发现和来源上架日期 | 同商品多店铺、多记录追加来源，不重复建候选 |
| 手动 ASIN | 选择站点，输入 ASIN 或支持的亚马逊商品链接；负责人、理由 | 创建候选后异步获取可得商品信息 | 展示排队/采集中/成功/部分成功/失败；失败保留候选，可人工补全或重试 |
| 非亚马逊产品 | 候选名称、负责人、理由必填；平台/供应商、图片、链接、规格可补充 | 系统候选编号，无需 ASIN | 无链接的样品或原创概念也能创建；不得伪造 ASIN |

站点下拉只展示当前支持范围；首期兼容现有美国站。不能因为能录入其他站点就宣称支持其采集和费用规则。

### 3.2 身份、重复与多竞品

- 系统生成独立候选编号，如 `CP-20261029-0001`，所有关联使用内部 ID；不使用 ASIN 作为候选主键或开发需求编号的必要组成。
- 同站点、同 ASIN 的默认入池操作复用原候选，并显示其状态。已淘汰候选提供“查看原因/重新评估”，不静默重开；已通过候选提供开发入口。
- 一个候选可关联多个参考商品，指定主参考商品；每个参考商品保留站点、平台及独立数据。添加次要竞品不改变候选身份。
- 非亚马逊产品按规范化平台链接/供应商货号提示可能重复；名称相同只提示，不强制合并。无可用身份时允许创建并记录理由。
- 本期不做候选自动合并。若同一竞品要做两种实质不同开发方向，通过“新建独立方案”显式创建并填写差异理由，保留关联原候选；默认导入仍提示已有候选供选择。
- 批量加入展示逐项成功、已存在、失败及原因；重试失败项不重复创建成功项。

### 3.3 最小创建与后续补齐

创建只要求可识别对象、负责人、入池理由，不要求先填完整成本和销量。未知字段保持空值；“资料未完成”与“采集失败”分别展示。

## 4. 核心数据结构与口径

一份候选包含：身份与来源、参考商品观测、拟开发规格、需求与改进条目、成本方案、风险清单、评分、评估版本、审批记录、开发关联。

### 4.1 每条关键证据都带来源

价格、销量、规格、费用、客户反馈等至少记录：值与单位、来源类型、来源链接或附件、观测/录入时间、统计期间（适用时）、录入人、可信性质（前台观测/人工录入/估算/待验证）。

- 未知不等于0；显示“待补充”或“未获取”。缺销量不记零销售，缺成本不记零成本。
- 商品首次上架日期、系统首次发现日期、入池日期分别保存。
- 自动更新参考商品数据不得覆盖人工拟定的规格、目标售价、评估意见或已审核快照。
- 当前观测与评估引用快照分开；有新数据时显示“来源有更新”，由评估人员查看差异后采纳。提交后只更新参考展示，不改送审内容。
- 不将竞品售价当成我方采购成本，不将竞品 ASIN 当成我方 SKU。

### 4.2 市场及销售数据

| 分组 | 字段 | 规则 |
| --- | --- | --- |
| 身份与链接 | 平台、站点、ASIN/货号、父子关系（可得时）、品牌、店铺、类目 | 明确单个子体或父体范围，不重复累计变体数据 |
| 销售表现 | 近30天销量、统计起止、销量口径、价格及币种、优惠条件 | 精确值、下界如50+、区间、估算分开存；可人工录入并附依据 |
| 评价与竞争 | 星级、评分数、评论数（如可得）、大小类排名及节点 | 评分数不等于评论数，BSR不自动换算销量 |
| 时效 | 来源上架日期、最近成功观测、采集状态 | 失败保留最近成功值并标注时间；新入池不补造历史趋势 |
| 对比 | 关联参考商品及历史观测 | 同币种/单位/期间才可直接比较；不一致时显式标记 |

亚马逊前台不保证提供精确销量。“过去一个月购买50+”保留原文和下界，不能显示为精确50，也不能据此计算确定销售额。精确销量、估算销量及平台展示购买量分别标识；竞品销售额仅在口径明确时作为估算展示。首期无需新增第三方付费数据服务。

无销售数据允许评估：填写“无可得数据”的原因、替代需求证据和验证计划；不因此自动否决或自动通过。

### 4.3 产品规格：现有事实与目标方案并排

规格表列为“项目 / 参考商品 / 拟开发目标 / 差异说明 / 来源或依据”。项目包括品名、类目、材质、功能、尺寸、净重、包装尺寸、包装重、颜色、套装数量、配件、包装方式、适配范围及自定义规格。

产品与包装尺寸不能混用；原单位保留，规范单位为 cm、g，转换结果注明。未知包装尺寸时履约费用仅能标为估算或待补充。拟开发规格允许以范围/目标值描述，进入开发时携带待验证项。

## 5. 客户需求与产品优化

### 5.1 需求条目

每条包含：目标客户、使用场景、需求/痛点、来源类型、证据引用、观察样本与期间、影响程度（高/中/低）、判断可信度（有证据/假设）、拟解决目标。

来源支持竞品评价摘录、问答、客户访谈、售后反馈、供应商反馈、市场观察。人工整理的样本量必须注明范围；例如抽看30条评论发现8条相关问题，只表示该样本，不能标为全部买家27%的痛点。

首次设计可使用假设，但须显著标注并给出验证计划；不能通过自动生成文本伪装已完成调研。

### 5.2 改进条目与开发建议

| 字段 | 说明 |
| --- | --- |
| 关联需求 | 对应需求条目，避免无依据堆功能 |
| 现有问题及修改建议 | 例如把连接件改为可拆卸结构，而不是笼统写“提升质量” |
| 改进类型 | 功能、结构、材质、尺寸、外观、配件、包装、使用体验 |
| 优先级 | 必须实现 / 建议实现 / 后续考虑 |
| 预期收益 | 解决的具体问题，不强制编造销量提升百分比 |
| 成本及供应影响 | 单位增量、模具/打样投入、交期、MOQ影响；引用成本行 |
| 验证方法与验收标准 | 测试方法、目标阈值或用户验证方式 |
| 风险/待确认事项 | 可制造性、适配性等未闭环问题及责任人 |

至少形成一条有依据的开发方向；如果结论是无需修改现有产品，则必须说明供应、渠道或组合方案等实际机会，不能用空改进项绕过评估。

## 6. 销售成本与利润试算

目标是支持立项决策的单件贡献试算，不是财务净利润报表，也不是亚马逊官方费用报价。首期延用已有计算能力并补齐字段及口径；费率和履约费由人工有依据填写，不写死为平台现行规则。

### 6.1 输入

- 目标销售市场、币种、预计实际成交价（明确是否含优惠、是否含税）、目标月销量假设。
- 单件固定成本：采购/制造、包装、配件、质检、头程、进口相关费用、履约配送、仓储分摊、其他单件成本。
- 按收入比例费用：平台佣金、广告、退货/售后净损耗准备。每项明确计费基数；若不适用当前简化公式，则以已核算单件金额录入并注明口径。
- 一次性投入：打样、模具、设计、检测等；MOQ、首批数量、预计首批采购及运输现金支出。
- 每行含原币金额、换算汇率、汇率日期、依据、报价/估算状态。汇率方向固定为“1原币=多少试算币种”。
- 单位成本、比例费用、一次性投入不可重复计算。退货准备仅含未在其他费用计入的净损失，不能与退款、折扣重复扣除。
- 缺必需值时可保存草稿，不输出完整利润；真实零费用允许，但必须填写依据。

### 6.2 计算与展示

设 P 为预计单件实际收入（采用明确的净收入口径），C 为换算后的单件固定成本，r/a/l 为同一 P 基数的佣金/广告/售后损耗比例：

- 单件贡献利润 M = P × (1 − r − a − l) − C。
- 贡献利润率 = M / P。
- 保本售价 = C / (1 − r − a − l)，仅分母大于0时可算。
- 可承受广告费率 = 1 − r − l − C/P；负值直接显示“未投广告已亏损”，不截断成0。
- 月贡献估算 = M × 目标月销量假设；明确销量是假设，与竞品销量独立。
- 一次性投入回收销量 = ceil(一次性投入/M)，仅 M>0 时有效；其余显示“当前方案无法回收”。不将已纳入C的分摊投入重复扣减。

基准、售价下降10%、单件固定成本上升10%三种情景并排；两个敏感情景独立计算，不暗示同时变化。保存多个试算方案，指定唯一“本次送审方案”，保留每次版本。

示例：P=20、C=8、r=15%、a=10%、l=5%，M=6、利润率30%、保本售价约11.43；售价下降10%时M=4.6，成本上升10%时M=5.2。目标月销100仅作为假设产生600月贡献估算。

首期不设置自动审批利润门槛。负利润或低分方案可提交，必须说明投入逻辑；审核人明确确认例外，不能消除提示。未解决阻断风险不能例外通过。

## 7. 风险、评分与审核门槛

### 7.1 亚马逊风险评估：独立步骤与必经审批条件

2026-10-29增补：风险评估从一般备注提升为独立工作步骤，候选详情新增“风险评估”页签。链路为“完成商业评估 → 完成风险调查并复核 → 提交立项审核”；调查可与需求和成本研究并行，但未完成不能通过。综合分再高也不能抵消阻断风险。新品开发阶段还需针对实际定型方案复核，不能只检查参考竞品。

**调查范围按拟销售国家/地区记录，不以中文商品名或单个ASIN代替调查对象。** 首期美国站默认美国销售市场；拟制造地、进口地及其他销售市场单独记录，有跨境权利疑问时转专业复核。多市场不能用“美国初筛通过”替代全部市场通过。

#### 7.1.1 调查类型

| 类型 | 必须覆盖的对象 | 需保存的证据与判断 |
| --- | --- | --- |
| 商标与品牌 | 拟用品牌、Logo、产品/包装上的文字标识、兼容品牌表述 | 检索词及变体、目标国家、相关商品/服务范围、相近标识、权利主体和检索链接；不能只查完全同名 |
| 版权 | 拟使用的图片、图案、插画、文案、说明书、包装设计及视频 | 原创作者/委托合同/素材许可、授权链、用途与期限；非原创无授权标待处理。不能因为搜不到登记记录就判定无版权 |
| 外观专利/外观设计权 | 产品整体及局部外形、装饰、组合部件 | 相关申请/授权号、国家、权利人、图示和法律状态来源，参考图与拟开发方案的对比记录 |
| 发明/实用类专利 | 核心功能、结构、连接方式、工作原理、制造方法 | 检索关键词/同义词、分类号/申请人等检索线索、公开/授权文件、权利要求相关点及方案对照；有疑似覆盖时转专业复核，不仅比较图片或摘要 |
| 亚马逊商品与类目要求 | 产品用途、人群、材料、功能宣称、拟售类目及目标站点 | 禁限售/准入要求、需准备的测试或证明文件及有效范围；记录当前政策链接和核查日期，不硬编码为永久规则 |
| 其他业务风险 | 安全、供应、物流、资金库存等 | 维持原清单、责任人及处理计划，与知识产权结论分开展示 |

“实用类专利”按目标国家的权利类型登记，美国utility patent与其他国家实用新型不混用。专利申请公开、授权、届满/失效和法律状态未核实分别记录；一个相关专利失效不证明所有相关权利均已排除。

#### 7.1.2 调查单与结果条目

每份调查单保存：候选ID、目标市场、调查类型、方案/图片/品牌版本、调查范围、负责人、调查日期、检索数据库、检索式、检索范围与局限、结果摘要、附件/链接、复核人和时间、下次建议复核日期。

每个命中结果保存：权利/申请编号、权利人、国家、名称、申请或公开/授权日期（可得时）、法律状态及查询时间、关联产品部位/素材/功能、疑似相关点、处理建议、专业意见（如有）、关闭依据。无命中也必须保存检索过程，不允许仅勾选“无风险”。

可从官方检索入口人工调查并录入，首期不承诺自动完成专利检索、权利要求分析或侵权判定。供应商提供的“无侵权声明”只能作为一项证据，不能替代调查。

授权证据须核对许可主体、产品/素材范围、地域、用途/销售渠道、期限及必要的转授权权限；“有采购发票”或“供应商说可以卖”不能自动等同取得相关知识产权授权。

#### 7.1.3 状态、结论与阻断规则

调查进度：未开始 → 调查中 → 待复核 → 已复核；重要变化后变为待重新评估。独立结论为：

- **初筛未发现明显风险**：在记录范围内已完成调查，由复核人员确认；不得显示“保证不侵权”。
- **已取得适用授权**：授权资料已核对，保留适用产品/市场/期限。
- **存在疑点，待专业复核**：疑似权利重合、状态不清、授权不足等；阻断立项通过。
- **需整改**：修改品牌/素材/结构/外观或补足授权后再评；未闭环前阻断。
- **不可接受**：停止当前方案，不可通过评分或普通例外强行放行。
- **不适用**：填写具体理由并经复核确认；不能将所有知识产权类别统一标为不适用来跳过调查。

状态描述的是调查工作与业务放行结论，不自动给出司法意义上的侵权认定。明确疑点需具备对应国家及权利类型能力的专业人士复核，系统只登记意见和依据，不能用AI生成“安全结论”代替。

提交立项审核前：每种调查类型均有调查结论或经复核的不适用依据；未解决疑点、需整改、不可接受项以及关键法律状态未核实均阻断。若类目测试需在开发打样后才能完成，可列为经审核认可的开发前置任务，明确验证时点；这不允许把未解决的知识产权疑点顺延放行。

#### 7.1.4 UI及联动

“风险评估”页签上方显示总状态、目标市场、方案版本、调查/复核负责人；下方按商标、版权、外观专利、功能结构专利、类目要求分组。每组显示调查进度、结论、证据数、最新核查时间及“查看调查单”。不要只放一个红黄绿分数。

列表增加“风险评估”状态列和筛选；点击进入对应页签。总状态取未关闭问题中的阻断状态，不按分数平均。检查面板可直接跳至缺失调查或具体疑点。

通过时冻结调查报告及附件引用，随开发基线交接；新品开发接收的可接受风险和后续验证任务必须逐项有责任人。品牌、用途、外观、功能结构、素材、目标市场或授权状态变化时，相关调查结论标记待复核，历史结论保留。

### 7.2 辅助评分

沿用五项0–5分：需求证据25%、差异化25%、利润空间20%、供应可行性20%、风险可控性10%。总分=Σ(单项分/5×权重)，保留1位小数；任一未填则显示未完成，不用默认50分或0分代替。

评分锚点：0=证据明确不支持；1=主要为假设且关键缺口多；2=少量证据、仍有关键待验证项；3=有可追溯证据及可执行方案；4=多项相互支持的证据、主要问题已核查；5=针对本候选有充分验证且结论明确。各维度理由应对应需求、改进、试算、供应和风险记录，不只填总分。

分数辅助比较，不自动审批。单独显示“送审必填完成度”和“数据可信性提示”，不把材料填满解释成高商业价值。

### 7.3 提交前检查

必须具备：负责人及候选理由、目标客户与场景、至少一条需求证据或明确假设及验证计划、目标规格/方案、改进建议或无需改动说明、选定完整成本试算、五项评分与依据、风险调查及复核结论、建议结论。

销量不可得不阻断，但须填写原因及替代验证依据。费用为估算不阻断，但须有估算依据与不确定性说明。规格的非关键项允许待验证；影响费用或可制造性的关键缺口须说明处理方案，不能留空后按零成本计算。

检查面板逐项显示缺失内容，点击跳至对应页签和字段；后端执行同一门槛，不能只靠前端隐藏按钮。

## 8. 状态与审批流

| 状态 | 含义与允许操作 |
| --- | --- |
| 待评估 | 新入池；补充基础信息、指定负责人、开始评估、淘汰 |
| 评估中 | 编辑研究、规格、成本及评分；提交审核、淘汰 |
| 待审核 | 送审快照锁定；审核人通过/退回补充/淘汰；提交人可撤回 |
| 待补充 | 显示具体退回意见；负责人编辑后重新提交，生成新送审版本 |
| 已通过 | 审批快照只读；查看对应新品开发草稿及后续状态 |
| 已淘汰 | 必填原因；保留资料与历史，具权限者可重新评估并填写理由 |

- 撤回回到评估中；退回和淘汰必须填写原因，通过必须填写结论。重新评估复用候选身份、开启新评估版本，旧审批不可改写。
- 同时显示候选状态与开发状态，不把“已通过”误认为“已开始开发”。
- 通过按钮文案“通过并生成开发草稿”，确认窗展示方案、关键风险、评估版本和负责人与审核人。
- 通过及创建开发草稿保持现有事务一致性，一候选最多一个关联开发需求；失败整体回滚，重试不重复建单。
- 已通过后不直接修改原送审版本。本期追加补充记录，并在开发流程处理方案调整；不增加自动覆盖开发需求或自动重复立项功能。
- 所有编辑/审批使用版本校验；冲突保留用户输入，提示重新加载对比。审批只针对所看到的送审版本，重复点击防重。

## 9. 与新品开发的交接

通过后自动生成现有新品开发模块的草稿，开发开始仍由开发人员执行。列表和候选详情显示“查看开发需求”，开发详情提供“来源候选”。

冻结并传递：候选编号及来源、主参考商品及其他竞品、目标客户/场景、需求证据摘要、拟开发规格、必须/建议改进项与验收标准、选定试算及币种/汇率/费用依据、一次性投入与数量假设、供应建议、可接受风险与验证任务、评分、审核结论和时间。

字段映射：拟开发名称→计划品名；拟开发材质/尺寸/重量→商品方案；拟采购成本→采购成本（保留币种并显式转换，不能把USD直接写成CNY）；需求与改进→研究摘要及可追溯评估包；供应建议→供货说明。无源数据留空，开发人员补充。主参考竞品参数不能直接充当我方目标参数。

开发员/采购员不从候选负责人无条件复制；开发周期、计划SKU及自有商品关联由开发阶段填写。非亚马逊候选以候选编号和名称承接，不能因没有 ASIN 报错。

既有手动创建新品开发需求入口保留，其权限规则不变；本次候选路径必须经审核，不改造成跳过审核的快捷入口。

## 10. 页面与交互设计

### 10.1 候选列表：紧凑评估台账

面包屑：**选品 / 候选池**。

- 顶部状态页签：全部、待评估、评估中、待审核、待补充、已通过、已淘汰；数量与筛选范围一致。
- 筛选：关键词（编号/名称/ASIN/货号）、来源、负责人、目标站点、类目、创建日期；高级筛选包含评分区间、试算情况、风险情况。“搜索”后执行筛选，“重置”恢复默认。
- 工具栏：主按钮“添加候选”；选中后可“分配负责人”“导出评估摘要”；不支持批量通过，避免跳过逐个评估。
- 列顺序：勾选、图片、候选名称/编号/ASIN、状态、来源、负责人、目标售价、近30天销售表现、单件贡献/利润率、综合分、送审完成度、风险提示、更新时间、操作。
- 左侧固定勾选/图片/候选身份，右侧固定操作；中间单一横向滚动。未知数值显示“—”并提供缺失说明，销量下界保留“+”，利润显示所选方案及币种。
- 操作以“详情”为主，次级菜单按状态提供开始评估、分配、淘汰等。已通过显示开发关联；不在列表铺开完整编辑表单。
- 默认按最近更新时间倒序；采用服务端筛选分页及现有固定底部分页，不新增大数据性能专项。

### 10.2 添加候选弹窗

两类入口页签：“亚马逊商品”“其他产品”。监控页面加入时复用相同表单并预填来源。40px编辑控件，必填提示清楚；保存成功进入详情，异步采集在详情展示进度，不阻塞整个页面。误点遮罩不关闭，未保存退出确认。

### 10.3 候选详情：先看结论，再查依据

面包屑：**选品 / 候选池 / 候选详情**，候选池可点击返回并保留列表筛选。

固定摘要区：图片、候选名称/编号、来源与负责人、状态、来源链接；右侧按状态展示“保存”“提交审核”或审核操作。概览指标四项：目标售价、预计单件贡献及利润率、综合分、送审完整度。指标无有效数据时显示待完善，不填假数字。

| 页签 | 内容及重点交互 |
| --- | --- |
| 评估概览 | 入池理由、目标客户和产品机会、建议结论、关键优势/风险、待补充清单、开发关联；评审第一屏能看懂为什么要做 |
| 市场与销售 | 来源商品卡片、销售与评价、数据时效/可信性质、关联竞品对照；“更新参考数据”有进度与部分失败反馈 |
| 产品方案 | 参考规格与目标规格对照、配件/包装、关键差异；目标字段人工编辑 |
| 需求与改进 | 需求列表及证据、改进列表；点击需求看到对应建议，点击建议看到费用影响和验收标准 |
| 成本与利润 | 左侧方案选择及费用录入，右侧计算摘要和敏感性分析；窄屏上下排列，保存/试算操作始终可见 |
| 风险评估 | 商标、版权、外观及功能结构专利、类目要求；调查证据、疑点处置与复核结论 |
| 评审与记录 | 五维评分、风险调查摘要、送审检查、审核意见；按时间展示版本、退回、通过、开发创建等事件及历史快照 |

证据在所属需求/规格/费用旁直接引用；“全部证据”作为详情辅助抽屉，不额外迫使用户切页签找出处。证据支持HTTPS链接、图片或文件上传，复用现有文件存储和访问控制；上传类型/大小在控件旁显示，失败可重试。已有只保存链接的证据原样可读；新上传能力须完成前后端接入后才展示入口。

编辑页签切换保留草稿；显式保存成功提示，失败保留输入；提交时先保存并校验当前完整版本，不审批未保存字段。待审核与已通过展示只读快照，并有明显版本时间。

视觉遵循UI_STANDARD：12px页面边距、8px模块间距、32px筛选及工具按钮、40px编辑控件、统一状态标签、图片contain。TableViewport和ListPagination复用；1280×800、800×600、360px均验证操作可达、表格可横滚、固定列不占满手机宽度（小屏改身份卡片+横滚数据，保留信息与操作），不整体缩放界面。

## 11. 数据兼容与研发约束

- 保留旧候选ID、来源、评审记录、证据、试算及开发关联；不得因新版缺字段而降级或重新审批历史已通过候选。
- 旧 NEW→待评估；旧 REVIEWING→评估中（旧状态不证明已完成新版送审），APPROVED/REJECTED保持已通过/已淘汰。页面注明历史记录和旧审核规则。
- 旧原始分数与研究加权分数分开迁移：有完整五项研究则保留综合分；仅有手填score则列为“历史手填分”，不冒充新评分。
- ASIN可空、站点商品身份与候选身份拆分；独立方案例外须显式建模，不能保留单一全局ASIN唯一约束后导致非亚马逊或多方案无法创建。
- 审批使用冻结评估版本，研究/费用变化不能绕过版本冲突；审计追加记录，不物理改写历史审批。
- selection与development通过公共事件/接口交接，维持模块边界；开发创建唯一键及事务回滚继续生效。
- 首期仅使用现有亚马逊采集能力。新增市场字段若当前无数据，则人工补充或显示未获取，不以界面字段存在宣称采集已实现。
- 上传访问、跨角色读取、修改/审批权限由服务端校验；新增链接不能让后台任意抓取内网地址，自动采集仍限已有支持的商品来源。

## 12. 范围与建议实施顺序

**本PRD的首期交付应覆盖完整评估闭环**，以下是研发顺序而非删减用户目标：

1. 候选身份及四来源、旧数据兼容、列表与详情新布局。
2. 销售事实引用、目标规格、需求/改进/证据及成本试算。
3. 版本化送审、风险与评分校验、审批及非亚马逊候选开发交接。
4. 完整回归、权限与失败场景验证、本地验收。

后续再考虑：AI辅助归纳评论、自动估算销量、第三方市场数据、自动查询平台费用、多级审批、自定义评分权重、成本模板共享、多币种会计核算、自动供应商询价。首期不得放不可用的空入口。

## 13. 验收标准

| 编号 | 场景与通过标准 |
| --- | --- |
| A01 | 产品监控/上新监控加入同一站点ASIN只复用一个默认候选，来源均保留；不覆盖负责人和已填方案 |
| A02 | 手动ASIN异步采集有进度，失败后候选和人工内容保留；重复重试不重复建档 |
| A03 | 无ASIN、无外链的非亚马逊样品可建档、完成评估、审批并进入开发 |
| A04 | 销量50+按下界展示；缺销量显示未知；不可据此生成精确销售额或评分 |
| A05 | 参考商品更新不覆盖目标规格和试算；送审后新数据不会修改审批快照 |
| A06 | 需求、证据、改进、成本影响及验证标准可互相追溯；假设与事实明确区分 |
| A07 | 未知成本不能当零，混币缺汇率不产出完整结果；示例基准及两个敏感情景结果正确 |
| A08 | 一次性投入与单件成本不重复扣除；贡献非正时不显示可回收销量 |
| A09 | 缺必填可逐项定位；无销量但有说明及替代证据可送审；关键风险未解决不可通过 |
| A10 | 待审核只读；撤回/退回/重提形成新版本；无权限、过期版本、重复请求均被服务端处理 |
| A11 | 审核通过与开发草稿同事务，一候选一个关联需求；创建失败候选仍待审核，无半成功 |
| A12 | 开发继承批准的目标方案及试算快照，不把竞品售价当采购成本，不自动创建SKU |
| A13 | 已通过历史候选、开发关联和追加式证据不丢失；旧手填评分不冒充新版综合分 |
| A14 | 列表筛选/分页一致，所有列可访问；三个标准视口无按钮裁切；弹窗取消不丢未保存输入 |
| A16 | 调查未完成/疑点未闭环不能通过；无命中保留检索依据，不生成“无侵权保证”；授权范围不符须阻断 |
| A17 | 销售市场、方案或素材变化触发对应风险重新评估，旧结论和来源证据可追溯 |
| A15 | 原监控采集、60天新品识别、已有新品开发及手工开发入口无回归 |

研发阶段按仓库要求执行受影响的前后端完整质量门禁、数据库迁移演练、HTTP权限/异常测试及真实浏览器验收。本轮仅PRD，不将上述验收项标记为已实现。

## 14. 本版建议确认的业务默认值

本版按以下默认方案设计，可在评审时调整：

1. 通过后自动生成开发草稿，沿用现有机制；不自动开始开发。
2. 综合分不设置自动通过线，审核由人员作出；阻断风险不能通过。
3. 无销量、非亚马逊或原创概念允许入池和审批，但须提供替代证据及验证计划。
4. 审核权独立于编辑权，默认管理员审核；自审需明确确认并留痕。
5. 旧候选及已开发记录保留，只有新送审版本适用新门槛。

- [美国版权局：什么是版权](https://copyright.gov/what-is-copyright/)：版权调查不能仅以注册数据库是否有记录为依据，须核对素材创作与使用权限。
