# 工厂计件报工与月度工资管理 PRD v1.0

- 日期：2026-10-30
- 状态：用户已授权开发；首版已在原本地环境部署（2026-10-31），未提交或合并 main。下文保留原设计，实际交付差异见文末。
- 目标：将员工每天报数量、人工记工钱、月底加总的流程，改为可核对、可追溯的计件工资台账。
- 依据：用户需求、提供的手写工资参考图片、现有商品与产品成本模块、[UI 规范](../ui/UI_STANDARD.md)。
- 首期建议：管理人员代录报工，不要求工人使用系统；按自然月、人民币计薪。需要员工自行填报时，再扩展独立移动端入口。

## 1. 从现有手写账到系统流程

参考图片按员工分块，记录加工名称、数量、单价、金额及个人合计。同一员工加工多种产品，同一产品可能涉及包边、压线、贴魔术贴、包装等不同工序。图片无法可靠区分所有名称、工序和统计日期，因此只作为业务及版面参考，不自动导入为工资记录。

图片右下角单列了耗材等开销。这类支出不计入个人工资，也不自动摊给员工；本期工厂模块只处理人工报工及工资，工厂费用账后续单独规划。

建议主流程：

**维护员工 → 建加工项目及工序工价 → 每日录入数量 → 核对报工 → 生成月度工资 → 核对并锁定 → 登记发放。**

日常使用重点是“录得快、算得对、月底查得到”。不要求先建生产订单，不将简单计件记账扩大为完整生产管理系统。

## 2. 菜单与首期范围

新增一级菜单“工厂”，建议放在“商品”之后、“发货”之前。

| 二级菜单 | 主要用途 | 主要入口 |
| --- | --- | --- |
| 员工管理 | 维护工人档案、在职状态及历史工资 | 新增员工、详情、离职 |
| 工价管理 | 管理加工项目、工序、计价单位和历史工价 | 新增工价、调整工价、项目与工序 |
| 每日报工 | 按员工和日期批量录入加工数量，核对工钱 | 新增报工、批量核对、详情 |
| 月度工资 | 汇总计件工资、调整项、已发及未发金额 | 生成本月工资、核对锁定、登记发放、导出 |

工价管理内维护加工项目与工序，不额外增加大量主列表菜单。员工详情可查看个人报工和工资；月度工资详情可追溯原始报工，避免重复维护。

首期包含：计件工资、标准工价及可选员工专属工价、批量代录、报工核对、工资调整、月结锁定、分次发放登记、工资单打印和表格导出、权限与审计。

本期不包含：考勤打卡、计时排班、底薪规则引擎、自动税费与社保核算、银行付款、生产排程、库存自动入库、自动从手写图片生成正式工资。确有固定工资或补贴时，可先用明确分类的人工调整项登记，不推算未提供的规则。

## 3. 核心业务对象

| 对象 | 定义与约束 |
| --- | --- |
| 员工 | 独立工号，不等于 ERP 登录用户；允许同名，历史记录以员工ID识别 |
| 加工项目 | 工人熟悉的产品或加工件名称；可关联已有产品或具体SKU，也可手动建立未建档加工件 |
| 工序 | 可重复使用的工序，如包边、压线、贴魔术贴、包装；同名产品的不同工作必须分开 |
| 工价版本 | 加工项目＋工序＋单位＋适用对象＋生效日期对应的计件单价 |
| 报工单 | 一个员工、一个工作日期下的一次报工，可含多条加工明细；同日允许分批上报 |
| 月度工资单 | 一个员工、一个工资月份的一张工资单，包含计件明细与调整项 |
| 发放记录 | 对已锁定工资的支付事实登记，不执行真实转账 |

已有产品成本模块中有工序字典和人工成本方案。工厂工序应复用已有工序身份，保留现有工序的引用；实现时通过公开服务接口联动，不直接读取其他模块内部类型。工资工价独立版本管理，不能直接修改已发布成本方案。

## 4. 员工管理

### 4.1 信息维护

必填：员工姓名、入职日期；工号自动生成且唯一。选填：手机号、班组、常做工序、备注。状态为在职/离职，离职日期单独记录。

首期不要求身份证、银行卡或地址，不为每位员工自动创建登录账号。可选关联已有登录用户，供未来“仅查看本人”能力使用；默认不开放。

列表字段：工号、姓名、班组、手机号、常做工序、入职日期、在职状态、操作。按关键词、班组、状态筛选，默认显示在职。

详情页签：基本资料、报工记录、工资记录、操作记录。与用户/角色详情一样使用固定头尾和页签，明细分页。

### 4.2 历史保留

有报工、工资或工价引用的员工不能物理删除，只能离职。无引用且误建的员工可移除并留痕。离职不能隐藏未结工资；离职后仍允许核对、补发及补录其在职日期内的工作。

报工工作日期必须处于任职日期范围内；姓名、手机号变更不改写已锁定工资单的显示快照。

## 5. 工价管理

### 5.1 加工项目与商品关联

选择已有产品或SKU后自动带出名称和图片，工厂可维护“加工名称/别名”，方便按工人口头名称检索。未在商品库建档的加工件允许手动新增，不强迫创建亚马逊商品或ASIN。

工价始终绑定加工项目。若不同SKU规格工价不同，必须建立不同加工项目并明确关联SKU；不能仅按相似名称自动匹配或从父体价格隐式继承。

### 5.2 工价字段及列表

字段：加工项目、工序、计价单位、单价、生效日期、适用对象、状态、备注。单位支持件、套、条、个等明确单位；箱、批必须在名称或说明中明确包含数量，不自动与件换算。

默认适用全部员工。确需按员工约定工价时，可新增“员工专属工价”，显式选择员工并说明原因；不根据图片中看似不同的价格推定存在专属工价。

列表字段：加工项目/关联SKU、工序、单位、当前工价、适用员工、生效日期、状态、操作。详情展示历史价格版本与引用报工数量。

### 5.3 生效与匹配规则

1. 按工作日期匹配价格，不按录入日期或当前日期匹配。
2. 同一项目、工序、单位、适用对象的版本生效区间不能重叠；新版本从指定日期生效，旧版保留。
3. 对应日期存在员工专属工价时优先使用，否则使用标准工价；界面标明匹配来源。
4. 找不到工价时允许保存待完善草稿，不能核对或进入工资。未知工价不能默认为0。
5. 零单价仅在明确选择“不计薪”并说明原因后允许，默认不启用；正常工价必须大于0。
6. 改价默认从未来日期生效。允许有权限者补建历史版本，但必须显示受影响记录，并说明原报工不会自动重新计算。
7. 报工保存时冻结单价、版本、单位、项目及工序名称。改变日期、员工或加工项目后重新匹配，保存前展示金额差异。
8. 草稿可显式“采用适用工价”重算；已核对明细必须撤回重核；已锁定工资只能走更正流程。
9. 停用项目/工序后不允许新增未来报工，仍可追溯和按历史有效范围补录；有引用的版本不可删除。

录入员不直接改报工单价。特殊价格通过有权限人员维护工价版本解决，防止录入时随意覆盖单价。

## 6. 每日报工

### 6.1 高效录入

默认工作日期为今天。新增弹窗上方选择日期和员工，下方连续添加行：加工项目、工序、单位、数量、单价、金额、备注。日期、员工、工序均可搜索，工价自动带出。

支持两种录入模式：

- 按员工录入：同一员工当天做了多种活，连续填多行；默认方式。
- 按项目录入：同一加工项目分给多位员工，每行选择员工与数量，保存后生成各员工独立报工单。

提供“再加一行”“保存并录下一人”和“复制上次项目”。复制只带项目/工序，不复制数量，日期默认为当前所选日期并重新匹配价格，防止重复记工。

支持键盘Tab顺序填写。数量输入后立即显示预计金额，最终金额以服务端计算为准。取消未保存内容须确认；失败保留输入，连续点击保存不得生成重复记录。

### 6.2 数量与重复录入

计薪数量为核对后认可的加工数量，不另建强制质检流程。若员工报100件、实际认定98件，核对者修改为98并保留原数量及原因。图片未体现不良品规则，系统不自动扣不良品或推算损耗。

数量默认整数；项目明确允许小数单位时最多3位小数。保存/核对时校验单位和精度。负数不作为正常报工；更正用关联原明细的冲销或补差。

同员工、同日期、同项目、同工序出现多条记录时提示“可能重复”，展示既有数量与金额；允许经确认登记不同批次，填写批次或说明。不能用唯一键把真实多次加工拒绝掉，也不能完全不提示。

报工单按整单保存：任一行校验失败则不提交整单，定位错误行；批量核对同样先校验全部所选单据，失败不部分核对。请求幂等与业务重复提示分别处理。

### 6.3 状态与操作

状态：草稿 → 待核对 → 已核对；退回后回到草稿，作废保留记录。列表显示工资关联状态，已锁定工资覆盖的明细不能编辑。

录入人可保存草稿或提交核对。有核对权限的管理人员可以“保存并核对”，减少小工厂重复操作；自录自核不禁止，但记录同一操作人。

未被锁定工资引用的已核对单可按权限撤回，填写原因；工资草稿随即标为来源已变化。作废、数量调整、撤回均记录操作者、前后值和时间。

### 6.4 列表与详情

默认查看今日，支持日期范围、员工多选、项目/工序、状态与关键词筛选，点击搜索后应用。

列表按报工单一行展示：工作日期、员工、明细项数、加工摘要、计件金额、状态、工资月份、录入人、更新时间、操作。不同计价单位不汇总成一个“总件数”。

详情页签：报工明细、核对记录。允许附报工凭证图片，但不强制；附件上传、查看和下载均受工资权限控制。

## 7. 工资计算口径

- 币种固定人民币。所有计算使用十进制定点数，禁止浮点误差。
- 工价最多6位小数；数量最多3位；行金额＝计薪数量×单价，四舍五入到分。
- 日/月计件工资＝所属有效明细行金额之和；不能先将不同工价合并再四舍五入，避免明细与总额不一致。
- 月度应发＝本月计件工资＋其他加项－其他减项。
- 月度待发＝应发－有效发放记录合计。预支如已实际支付，应登记为预支发放并绑定工资月份，不能再作为扣款扣一次。
- 单价和数量单位必须一致。发生单位换算时必须由项目定义明确比例，不根据文字猜测。
- 不同员工、不同价格版本、不同单位保留独立分组，个人明细可按“日期”或“项目＋工序＋单价”汇总，后一种接近参考手写账。

验收用合成算例：员工甲当天包边120件×0.40元＝48.00元，压线75件×0.70元＝52.50元，计件合计100.50元；加补贴20元、减已确认调整5元，应发115.50元；已登记预支30元，待发85.50元。此为虚构算例，不是附件员工工资。

## 8. 月度工资

### 8.1 月份与生成

工资月份默认自然月，工作日期属于哪个月就计入哪个月。生成工资仅纳入已核对且未作废的报工；待核对与缺价记录显示异常数量和跳转入口，不静默忽略。

同一员工同一月份仅有一张有效工资单。整月批量生成包含当月有已核对报工、调整或预支的员工，包含当月离职员工；可手动为零报工员工生成工资单维护补贴等项目。

生成和重复点击均幂等。草稿包含来源版本及计算时间；新报工或更正后显示“数据有变化，待重新计算”，禁止以过时结果锁定。重新计算显示前后差异，保留人工调整项。

### 8.2 调整项

类型包括补贴、奖励、计时/固定工资人工补录、其他加项、其他减项。金额输入正数，由类型决定加减；必须填写具体用途及所属月份，可附凭证。

普通备注和正常保存不要求变更原因；会影响金额的调整、撤回、作废和重开必须说明原因。负应发工资不自动转成欠款，阻止锁定并提示核对调整项。

### 8.3 核对与锁定

工资生命周期为草稿、已锁定、已作废；发放进度另列未发、部分发放、已发清，避免混淆工资核算与付款。

锁定前检查：来源版本最新、当月该员工无待核对/缺价异常、重复报工提示已处理、调整项完整、金额一致。未处理记录必须完成核对或明确作废后才能锁定。

锁定同时冻结所有明细与合计，后续更改员工姓名、项目名称和价格不影响该版工资单。锁定按钮展示员工人数和应发合计，批量操作全部通过校验后一次生效。

员工月份锁定后禁止普通补录进入该月份。后续迟报须选择“更正已锁定月份”，不能创建无法结算的孤立报工。

### 8.4 更正和补发

- 已锁定且未发生任何发放：有权限者填写原因后重开，旧版保留，补录/修改后重新核对并锁定。
- 已有预支或其他发放：不覆盖原锁定快照；创建关联原工资单的更正单，展示原值、调整明细与差额，审核后形成新版本，旧发放记录继续计入已发。
- 增加的金额列为待补发；减少后如已发超过应发，显示“待处理超发”，阻止继续发放，不自动从其他月份扣回。
- 更正后原月工资归属不变，跨月实际付款按实际发放日期记录。月度核算与付款统计分别提供口径。

### 8.5 发放登记

在锁定工资中登记本次金额、日期、方式（现金/银行/其他）、经办人、备注和可选凭证。允许分次发放，服务端防止并发超额登记；默认金额为待发余额，不代替人工确认付款事实。

预支可在工资草稿阶段登记，但必须明确员工及归属月份，金额不受尚未核算的应发上限限制；锁定时如预支超过应发，必须作为超发异常处理。正常工资发放仅允许在已锁定后进行。

误登记只能作废发放记录并说明原因，保留历史；作废登记不会撤销真实银行付款。系统不连接银行自动转账，不把“工资已锁定”当作“已付款”。

### 8.6 列表与工资单

列表字段：工资月份、工号/姓名、班组、报工天数、计件工资、加项、减项、应发、已发、待发/超发、核算状态、发放状态、操作。报工天数为去重工作日期数，不作为考勤出勤天数。

员工详情弹窗页签：工资概览、计件明细、调整项、发放记录、操作记录。点击金额或异常项可定位明细，所有记录分页。

导出：月工资汇总表、报工明细表、单人工资单。工资单支持浏览器打印，包含所属月份、核算版本、生成时间、逐项工序与工价、应发/已发/待发，草稿明显标注“未锁定”。多人打印必须分页，避免个人工资混在一页。

## 9. UI 与使用体验

沿用上新监控、产品监控、候选池、新品开发的统一风格，不新增独立端口或另一套管理界面。

列表页面从上到下为紧凑筛选栏、操作栏、数据表、固定底部分页。日期复用DatePicker，多选复用FilterMultiSelect，单选复用现有控件。查询由搜索按钮/Enter触发；汇总金额基于全部筛选结果，不仅是当前页，并标明统计口径。

主操作为蓝色，批量核对在有可核对选中项时启用并显示绿色；作废/删除用红字确认。工资详情的已锁定状态和待发金额优先展示，避免只给一张信息拥挤的大表。

每日录入示意：

| 工作日期 | 员工 | 班组 |
| --- | --- | --- |
| 2026-10-30 | 员工甲 | 缝制组 |

| 加工项目 | 工序 | 数量 | 单位 | 自动工价 | 金额 |
| --- | --- | --- | --- | --- | --- |
| 加工件A | 包边 | 120 | 件 | 0.40 | 48.00 |
| 加工件A | 压线 | 75 | 件 | 0.70 | 52.50 |

底部固定显示“本次计件合计 ¥100.50”与取消、保存草稿、提交核对；有权限时提供保存并核对。报工不要求输入一整月数量后才能保存。

表格采用TableViewport，金额右对齐且保留两位，项目和姓名不因横向滚动无法辨识；窄屏取消会遮挡主体的固定操作列。详情固定标题、页签和底部操作，中间独立滚动。

加载、提交、批量核对和导出显示忙碌状态，防止重复操作。新增、保存、核对成功给出明确反馈；报错定位到具体员工/行，保留草稿。权限不足时不展示不可执行操作，服务端再次校验。

## 11. 权限与数据保护

建议能力：员工查看/维护、工价查看/维护、报工查看/录入/核对/作废、工资查看/核算/锁定/更正、发放登记/作废、工资导出。

建议角色模板：工厂录入员负责日常记工；工厂负责人维护工价并核对；工资核算员核算锁定；出纳登记发放。一个人可兼任多个角色，沿用现有角色管理，不硬编码用户名。

工资权限与普通商品读权限分离；只有工厂报工权限的用户不能查询或导出全部员工月薪。普通审计中展示对象和动作摘要，工资明细差异需工资查看权限。附件、导出、历史版本、汇总接口均执行相同权限检查。

## 12. 数据与一致性要求

主要数据实体：员工、加工项目、工序引用、工价版本、报工单/明细、核对事件、月工资单/版本、工资调整项、更正单、发放记录。

引用关系保留稳定ID与业务显示快照；已锁定工资中的历史名称、单价、单位、数量和金额均可独立还原。每条报工明细在同一月份只能被有效工资版本计入一次，更正版本关联原条目，不追加为另一份重复收入。

工价版本使用日期区间和适用范围约束；工资单员工月份唯一；报工提交、核对、工资锁定、更正和发放采用事务、版本校验与幂等键。并发修改失败返回“已被更新，请重新加载”，不覆盖他人改动。

后端按员工、日期、状态和月份进行服务端筛选与分页；列表不一次拉取全部历史工资。工资计算不调用大模型，不消耗模型token；图片自动识别如后续增加，需单独设计人工核对与调用成本。

## 13. 历史账迁移与上线方式

先建立员工和当前工价，选一个完整月份并行试记，逐人对照手工台账，确认计价单位和工序拆分正确后切换。

历史月度只有汇总金额时，可提供“历史工资期初登记”：填写员工、月份、已核对应发、已发和来源说明，不伪造每天的报工。该入口独立权限、明确历史汇总标识；如以后补齐明细，必须走替换更正而非把汇总与明细同时相加。

首期可将历史期初登记放在月度工资的辅助入口；不做手写OCR批量入账。导入模板及自动识别列为后续扩展，现有附件需人工核验日期和金额后才能作为账目依据。

## 14. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 同员工一天做两道工序 | 分别匹配工价，合计与明细相符 |
| 同加工件不同规格/工序/员工约定价 | 按明确项目及适用范围匹配，不按名称猜价 |
| 次月补录上月未锁定工作 | 使用原工作日期价格，归入上月 |
| 当月中途改价 | 前后日期使用各自版本，已保存记录不自动改变 |
| 无工价、单位不匹配或数量错误 | 可保留合法草稿，不能核对或锁定工资 |
| 同日同工序重复报工 | 显示已有记录，确认不同批次才可继续 |
| 保存重试、重复生成、并发锁定 | 不重复产生收入或工资单 |
| 100.50元计件＋20元补贴－5元调整、预支30元 | 应发115.50，已发30.00，待发85.50 |
| 新增报工后打开旧工资草稿 | 显示来源变化，重新计算前不能锁定 |
| 离职员工仍有当月工资 | 自动纳入月结，可查询并发放 |
| 锁定后修改姓名或工价 | 已锁定工资快照及金额不变化 |
| 已付款工资补报 | 更正保留旧版、已付款事实及补发余额 |
| 更正减少工资导致超发 | 标记待处理超发，不自动跨月扣回 |
| 分两次发清、重复或并发登记 | 正确累计，阻止普通发放超额与重复请求 |
| 作废误登记的发放 | 恢复待发余额，保留完整审计链 |
| 无权限查看工资/导出/附件 | 菜单、接口、文件下载一致拒绝 |
| 参考图片中的耗材支出 | 不计入员工工资或自动扣减 |
| 1280×800、800×600、360px界面 | 表格可横滚、分页可见、弹窗按钮不被遮挡 |

## 15. 实施划分与评审事项

建议同一首期交付完整闭环，内部按三个阶段实施：

1. 员工、加工项目/工序、版本工价及权限。
2. 每日报工、快速批量录入、核对、重复提示及审计。
3. 月工资、调整项、锁定与更正、预支与分次发放、导出打印、历史期初登记及端到端验收。

在工资更正和幂等校验完成前，不应将试用数据当作最终工资发放依据。后续扩展再考虑员工手机自报、报工照片识别、计时工资、工厂费用及生产订单关联。

本稿采用以下业务假设供评审，不作为已确认事实：

- 员工每天口头/消息报量，由管理人员统一代录；暂不要求每人登录。
- 以自然月结算、以计件为主，补贴等由人工调整项维护。
- 工价通常按项目和工序统一，专属工价仅在明确需要时启用。
- 记录预支、分次发放及补差，但不执行银行转账。
- 不同手写名称的项目和工序由管理人员确认后建档，不自动认定为同一加工项目。
