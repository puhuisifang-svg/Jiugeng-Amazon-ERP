## 1. 项目目标

完成一个可试点的内部 MVP，使员工能够登录系统，统一维护多规格产品、产品对应辅料和单仓辅料库存；优先完成选品候选池，并实现一个指定 Amazon 美国站公开店铺的上新监控。店铺 Listing 映射已按 DEC-012 移出当前 MVP。

当前实现的实体、五类导入、API 资源和动作级权限以 [当前 MVP 活跃范围契约](MVP_ACTIVE_SCOPE_CONTRACT.md) 为准；Sprint 0 六类导入契约继续作为历史审计证据，不构成 Listing 实现授权。

## 2. 最终范围

### 2.1 登录与权限

- 内部账号密码登录、退出、首次登录改密、失败锁定、管理员解锁/重置、账号启停和审计。
- 三类角色：系统管理员、产品/辅料人员、选品人员。
- 前端菜单和后端接口双重鉴权；不做公开注册、只读角色、SSO、多租户和复杂数据权限。

### 2.2 产品与 SKU

- Product/SPU 下维护多个内部 SKU，颜色、尺寸、数量装等采用动态变体属性。
- 产品/SPU、内部 SKU 和辅料编码均由业务人员手动输入。

### 2.3 辅料与单仓库存

- 辅料主档及 SKU—辅料单层关系，记录标准用量、单位、损耗率和备注。
- 固定一个辅料仓库，支持期初、入库、出库、盘点调整、余额、不可修改流水和安全库存提示。
- 默认禁止负库存；不做采购、生产领料、成本、多仓、库位、批次或效期。

### 2.4 选品

- 手工录入 Amazon URL/ASIN，或接收上新监控发现的商品。
- 维护标题、图片、类目、价格、评分、评论数、来源、负责人、标签和选品理由。
- 流程固定为：待评估 → 评估中 → 通过/淘汰；美国站候选优先按 ASIN 查重。

### 2.5 指定公开店铺上新监控

- 配置一个公开店铺链接，每日采集商品快照。
- 首次成功采集只建立基线；后续按 ASIN 集合差异识别疑似新品。
- 失败、空结果和分页不完整快照不得覆盖有效基线；同一店铺同一 ASIN 只生成一次首发事件。
- 新品需人工复核后进入选品池。
- 采集使用可替换 `CollectorAdapter`。Sprint 0 先对 3 个样本店铺连续验证 7 天，再在合规第三方 API、低频公开页面采集或人工导入降级中确定生产方式；不绕过登录、验证码或访问控制。

## 3. 编码与关键数据规则

- 内部 Product、SKU 和辅料编码手动输入，必填且分别全局唯一。
- 格式统一为 1～64 位，正则 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`；允许字母、数字、短横线和下划线，不允许中文、空格及其他特殊字符。
- 保存时去除首尾空格，大小写不敏感判重，展示保留原输入。
- 编码修改仅系统管理员可执行，必须记录修改前后值；普通业务人员通过停用与新建纠错。
- ASIN、UPC/EAN/GTIN 均为独立字段，不得代替内部 SKU。
- 库存余额与流水同事务写入，以业务请求号幂等，流水不可编辑或删除。

## 4. 技术方案

- 前端：Vue 3 + TypeScript + Vite + pnpm。
- 后端：Java 21 + Spring Boot 3 + Maven Wrapper。
- 数据：MySQL 8；Redis 仅用于锁、缓存和任务协调；S3 兼容存储保存图片、附件、导入文件和采集证据。
- 架构：前后端分离的模块化单体，模块为 IAM/Audit、Product、Material/Inventory、Selection、Watch、Import/Export。
- 部署：Docker Compose 起步；敏感值只进入 Secret Store 或部署受保护变量。

## 5. Sprint 路线

| Sprint | 参考周期 | 交付 | 退出条件 |
| --- | --- | --- | --- |
| Sprint 0 | 1 周 | 字段/导入模板、低保真流程、3 店监控 Spike、脚手架与环境收口 | 数据源路线和字段基线明确；工程环境可构建 |
| Sprint 1 | 2 周 | 登录、三角色、账号管理、审计、基础框架 | 登录和越权测试通过 |
| Sprint 2 | 3 周 | Product/SKU、辅料关系、单仓库存、导入导出 | 真实样本可导入；库存余额与流水 100% 一致 |
| Sprint 3 | 2 周 | 选品池优先、店铺配置、采集适配器、快照、差异和新品事件 | 候选管理闭环完成；样本店铺建立基线并识别已知新增 ASIN |
| Sprint 4 | 1 周 | 联调、回归、备份恢复演练、试点和操作说明 | P0 缺陷清零，老板验收 |

周期为容量估算；每个 Sprint 必须由 PJM 提交计划、老板批准后才启动，并在老板验收后进入下一 Sprint。

## 6. 团队分工

- PJM：Sprint 计划、依赖/风险、成果核验和验收汇报。
- PM：字段、流程、PRD、导入模板和业务验收口径。
- UI：信息架构、原型、交互和视觉规范。
- Frontend：管理端、权限路由、表格表单、导入导出和联调。
- Backend：领域模型、API、库存一致性、采集任务、迁移和自动化测试。
- QA：测试计划、权限/库存/监控专项、回归和验收证据。
- Ops：Compose、CI/CD、Secret、备份恢复、监控和部署。

## 7. MVP 验收门槛

- 三角色后端越权拦截率 100%，关键操作审计覆盖率 100%。
- Product/SKU/辅料编码重复率为 0。
- 辅料库存余额与流水重算一致率 100%，负库存拦截率 100%。
- 1,000 行导入不超过 5 分钟，错误逐行返回且不静默丢数。
- 上新监控连续 7 天任务成功率不低于 95%，人工复核误报率低于 5%；失败快照不污染基线。
- P0 需求覆盖率 100%，发布时 P0 缺陷为 0，P1 无未批准遗留。
- 20～50 条脱敏真实样本完成导入核对，三类用户完成端到端试用，备份恢复至少演练一次。
