## 1. MVP 目标

首期只交付一个可试用的小闭环：员工登录系统，维护产品、对应辅料及辅料库存，把市场发现沉淀为选品候选，并监控指定 Amazon 店铺的新上架商品。

本期明确不做：生产、采购、成品库存、财务、多层 BOM、质检、链接全字段监控、评论/退货智能分析、多站点和移动端。

## 2. 功能范围

### 2.1 登录与权限

- 内部账号密码登录、退出、会话失效和管理员重置密码。
- 用户启停、登录失败锁定和首次登录改密。
- 三类角色：系统管理员、产品/辅料人员、选品人员。
- 菜单和接口权限；登录日志及产品、辅料、选品关键操作日志。
- 不做公开注册、多租户、企业 SSO 和复杂数据权限。

### 2.2 产品数据维护

- 产品主档（SPU）与多 SKU/规格维护；一个产品可包含多个颜色、尺寸或数量装 SKU。
- 核心字段：内部编码、中英文名称、类目、品牌、规格、材质、尺寸、重量、状态、主图和备注。
- Amazon 多店铺映射独立维护：内部 SKU 可分别关联 5 个店铺的 Seller SKU、ASIN、FNSKU、父子体、FBA/FBM 和 Listing 状态。
- MVP 通过界面和 Excel 导入维护 5 店 Listing 映射，不接入 SP-API 自动同步；自动同步后置。
- Amazon Catalog ASIN、父子变体与内部产品/SKU 分层保存，不用 Amazon 数据直接覆盖内部主档。
- 支持新增、编辑、查看、搜索、启停、Excel 导入和导出。
- 内部产品编码唯一；删除采用停用，不物理删除；关键修改留痕。
- 详细结构、唯一性和同步规则见 [产品与 Amazon 多店铺数据模型](../03-architecture/PRODUCT_DATA_MODEL.md)。

### 2.3 产品对应辅料维护

- 辅料主档：编码、名称、类型、规格、单位、图片、状态和备注。
- 类型首期支持：包材、标签、说明书、配件和耗材。
- 产品/SKU 与辅料建立一对多关系，记录标准用量、单位、损耗率和备注。
- 支持复制已有产品的辅料清单、Excel 导入导出和变更记录。
- 只做单层产品—辅料关系；不做多层 BOM、采购、生产领料和成本核算。

### 2.4 辅料库存维护

- 首期固定为一个辅料仓库，不提供多仓切换、仓库主档维护和仓库调拨。
- 辅料库存：按辅料维护现存数量、安全库存和最后变动时间。
- 库存业务：期初录入、手工入库、手工出库、盘点调整和库存查询。
- 每次变动生成不可直接修改的库存流水，记录业务类型、数量、前后库存、经办人、时间和备注。
- 默认禁止负库存；低于安全库存时在系统内提示。
- 库存恒等式：`现存数量 = 期初 + 入库 - 出库 ± 调整`。
- 不做多仓、仓库调拨、采购单联动、生产领料、在途库存、预占/可用库存、批次、效期、序列号、库位和金额成本。

### 2.5 选品

- 建立选品候选池，支持手工录入 Amazon URL/ASIN，也可接收上新监控发现的商品。
- 记录标题、图片、类目、价格、评分、评论数、来源店铺、发现时间、标签、负责人和选品理由。
- 流程：待评估 → 评估中 → 通过/淘汰。
- 支持备注、附件、查重、筛选和导出。
- 本期不承诺销量估算、AI 自动决策和评论语义分析。

### 2.6 任意店铺上新监控

用户输入一个 Amazon 美国站公开店铺链接，系统创建监控任务，按日生成商品快照，对比前后 ASIN 集合，识别新出现的商品并自动进入选品候选池。

## 3. 店铺上新监控实现方案

### 3.1 技术流程

```text
监控店铺配置
  → 数据源适配器
  → 原始页面/响应留档
  → ASIN 与商品字段标准化
  → 本次店铺商品快照
  → 与上次快照做集合差异
  → 新品事件
  → 人工复核
  → 选品候选池
```

核心实体：`WatchStore`、`StoreSnapshot`、`StoreSnapshotItem`、`NewListingEvent`、`SelectionCandidate`。

差异规则：`本次 ASIN 集合 - 上次有效 ASIN 集合 = 疑似新品`。首次采集只建立基线，不产生新品告警；同一 ASIN 在同一店铺只产生一次首发事件。页面不完整或任务失败时不得用空快照覆盖有效基线。

### 3.2 数据源选择

Amazon SP-API 可管理授权卖家自己的 Listing，并可按 ASIN补充 Catalog/Pricing 数据；它不直接提供任意竞争店铺的完整商品清单。因此“任意店铺发现新品”需要独立数据源。

按优先级采用：

1. **生产推荐：合规第三方数据 API。** 选择能按 Amazon seller/store 枚举商品的数据服务，验证授权范围、美国站覆盖、成本、限流、历史深度和 SLA。
2. **MVP 验证：低频公开页面采集器。** 只访问无需登录的公开页面，低频采集并保存证据；不得绕过登录、验证码、访问控制或反爬机制。页面结构和分页变化会带来稳定性风险。
3. **降级方案：人工导入 ASIN。** 可继续做已知 ASIN 变化观察，但无法自动发现此前未知新品。

采集逻辑必须封装为 `CollectorAdapter`，后续更换第三方 API 或采集方式时不影响快照、差异和选品业务。

### 3.3 可靠性与风控

- 默认每日一次，支持手工立即执行；本期不承诺实时监控。
- 分页完整性校验、重试、超时、限速和任务状态可见。
- 疑似下架需连续两次缺失才确认；上新事件先进入人工复核，降低误报。
- 保存采集时间、来源 URL、原始证据摘要和解析版本，便于追溯。
- 任何正式上线的数据源都必须先通过合规、稳定性和成本评审。

### 3.4 可行性 Spike

在正式开发前用 3 个不同规模的公开店铺连续验证 7 天：

- 是否能稳定识别店铺和分页中的 ASIN。
- 能否区分首次基线、新增、暂时缺失和重复商品。
- 页面结构变化、验证码、区域差异和请求失败比例。
- 第三方 API 与公开页面采集在成本、覆盖率和稳定性上的对比。

Spike 退出结论只能是：采用第三方 API、采用公开页面采集、限定支持范围，或暂时只做人工导入。未通过 Spike，不对“任意店铺”作生产级承诺。

## 5. MVP 验收标准

### 登录

- 三类角色能按权限访问菜单和接口，越权请求拦截率 100%。
- 登录、失败锁定、退出、禁用和重置密码均有测试证据。

### 产品与辅料

- 产品编码、辅料编码重复率为 0。
- 真实样本可完成产品、SKU、辅料及标准用量维护。
- 导入失败逐行返回原因，不静默丢数。
- 停用和关键修改均可追溯。

### 辅料库存

- 期初、入库、出库和调整后，库存余额与流水汇总一致率 100%。
- 默认负库存拦截率 100%，低库存提示按安全库存阈值正确触发。
- 库存流水不可直接修改或删除；需要纠错时使用反向调整并保留原因。
- 单仓库存查询、流水汇总和导出结果一致。

### 选品

- 手工录入和监控发现的商品可进入同一候选池并按 ASIN 查重。
- 状态、负责人、依据和淘汰原因可追溯。

### 上新监控

- 一个样本店铺成功建立完整基线。
- 已知新增 ASIN 在下一次成功采集后 24 小时内生成事件。
- 同一新增 ASIN 不重复生成事件。
- 采集失败可见、可重试，失败快照不污染有效基线。
- 连续 7 天样本任务成功率不低于 95%；人工复核误报率低于 5%。
