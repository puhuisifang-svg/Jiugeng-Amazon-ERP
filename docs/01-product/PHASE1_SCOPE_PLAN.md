## 1. 已确认的业务基线

- 公司类型：工贸一体企业，产品研发、物料与生产管理是核心业务链路。
- 首期站点：Amazon 美国站。
- 首期店铺：5 个公司内部店铺。
- 业务第一优先级：产品管理、辅料/物料管理、生产管理。
- 业务第二优先级：选品、对标店铺上新监控、链接监控、用户需求分析。
- 系统基础能力：登录、用户、角色、数据权限和审计。
- 当前状态：规划评审中，Sprint 0 尚未启动。

## 2. 规划原则

1. 先打通“产品定义 → BOM/辅料 → 生产执行 → 成品入库”的工贸闭环。
2. 登录与权限虽然不是主要业务价值，但属于所有模块的技术前置，应先实施。
3. 选品模块分为“官方数据能力”和“补充数据源”，禁止把不稳定抓取当成既定基础设施。
4. 首期不扩展加拿大、墨西哥、欧洲和多平台。
5. 首期不建设完整 MES、设备联网、工资计件、财务总账或复杂 APS。
6. 重要主数据、BOM、生产单和监控事件必须版本化、可追溯、有审计记录。

## 3. 首期产品结构

### 3.1 平台基础与登录（技术 P0）

功能范围：

- 账号密码登录、退出、会话续期和强制失效。
- 密码复杂度、失败锁定、重置和首次登录改密。
- 用户、部门、岗位、角色、菜单和按钮权限。
- 数据范围：部门、产品线、店铺和仓库。
- 登录日志、操作日志和关键数据变更审计。
- 账号启停、离职禁用和管理员重置。

首期不包含：社交登录、对外注册、多租户、复杂身份联邦。企业 SSO 和 MFA 可在部署环境明确后评估。

### 3.2 产品管理（业务 P0）

功能范围：

- SPU、SKU、款式、变体、品牌、类目和产品线。
- 内部产品编码、中文/英文名称、规格、尺寸、重量、材质和包装信息。
- 产品图片、说明书、设计文件、质检标准、认证资料和附件。
- 产品生命周期：提案、打样、评审、在产、停产、淘汰。
- 产品版本与变更单，保留变更原因、生效时间和影响范围。
- SKU 与 ASIN、MSKU、FNSKU、5 个店铺 Listing 的映射。
- 批量导入、重复校验、字段完整度和修改历史。

首期关键规则：一个内部 SKU 必须有唯一编码；发布过的产品版本不能直接覆盖；Amazon 映射与内部产品主数据分离。

### 3.3 辅料、物料与 BOM（业务 P0）

功能范围：

- 原材料、辅料、包材、标签、说明书、半成品和成品分类。
- 物料编码、规格、单位、换算关系、供应商、采购周期和安全库存。
- 替代料、损耗率、最小领料单位、批次/效期属性。
- 单层与多层 BOM，BOM 版本、审批、生效/失效日期。
- BOM 用量展开、替代料规则和变更影响分析。
- 物料库存、入库、领料、退料、补料、报废和库存流水。
- 产品、BOM、工艺路线和质检标准的关联。

边界：首期提供支撑生产的物料库存，不扩展成完整采购结算和供应商财务系统。

### 3.4 生产管理（业务 P0）

功能范围：

- 生产需求、生产计划和生产工单。
- 工单创建、审批、下达、暂停、恢复、完工和关闭。
- 工单冻结 BOM 版本、计划数量、批次、交期和责任部门。
- 备料检查、领料、退料、补料和实际耗用。
- 工序/工艺路线、开工、报工、在制数量和完工数量。
- 质检、合格、不合格、返工、报废和异常原因。
- 成品入库、批次追溯和工单进度看板。
- 计划用量与实际耗用、计划产量与实际产量的差异分析。

首期采用基础 MRP/齐套检查，不做分钟级 APS 排程、设备 IoT、Andon 或复杂车间自动化。

### 3.5 选品与市场情报（业务 P1）

#### A. 监控对象

- 对标店铺观察清单。
- 对标 ASIN/链接观察清单。
- 关键词、类目和细分需求主题观察清单。
- 监控对象标签、负责人、优先级和观察原因。

#### B. 对标店铺上新监控

- 记录对标店铺和已知商品集合。
- 按计划生成快照并识别新增、下架和重新上架。
- 新品事件包含首次发现时间、ASIN、标题、类目、图片、价格和变体摘要。
- 去重、误报复核、负责人分派和消息提醒。

约束：SP-API 没有直接提供“任意竞争店铺完整商品列表”的标准能力。Sprint 0 必须验证合规数据源；无法自动枚举时，先采用人工导入 ASIN/链接观察清单，再逐步接入批准的数据服务。

#### C. 链接监控

- 自有 5 店 Listing：可售状态、搜索抑制、Listing 问题、标题/图片/属性变化、价格和库存摘要。
- 对标 ASIN：标题、主图、变体、价格、评分、评论量、类目排名及可获得的 Offer 信息。
- 变更快照、字段差异、告警规则、处理状态和历史趋势。
- 支持监控频率、静默时间、阈值和告警合并。

#### D. 用户需求分析

- ASIN 与类目层面的正负面评论主题、提及量和趋势。
- 退货主题、使用场景、痛点、期望功能和未满足需求。
- 搜索词表现、需求主题聚类、机会点和证据引用。
- 分析结论必须能回溯到数据源、时间范围、样本量和算法版本。
- 输出选品卡片：目标用户、核心问题、建议卖点、风险和验证动作。

## 4. Amazon 数据能力边界

| 能力 | 首选数据源 | 规划结论 |
| --- | --- | --- |
| 自有 Listing 创建与维护 | Listings Items、Feeds、Product Type Definitions | 官方支持 |
| 自有 Listing 状态/问题变化 | Notifications、Listings Items | 官方支持，优先事件驱动 |
| ASIN 基础信息、图片、变体、类目和排名 | Catalog Items | 官方支持，受权限和限流约束 |
| ASIN Offer/竞争价格 | Product Pricing | 官方支持，需按授权与限流设计 |
| 评论主题、退货主题和趋势 | Customer Feedback API | 美国站可用；需 Brand Analytics/相应角色 |
| 搜索需求表现 | Brand Analytics 报告 | 适用于符合资格的品牌/授权数据 |
| 任意竞争店铺完整商品清单及上新 | 无直接标准 SP-API | 必须做合规数据源 Spike；首期准备人工观察清单降级方案 |

公司自用应用优先注册 Private SP-API Application，由公司自授权 5 个店铺。所有授权凭据只进入受保护的 Secret Store。

## 5. 核心角色

- 系统管理员：账号、角色、组织、权限、基础配置。
- 产品经理/产品开发：产品、版本、附件、Amazon 映射和变更。
- 采购/物料专员：物料、供应商属性、安全库存和替代料。
- PMC/生产计划：需求、齐套检查、生产计划和工单。
- 仓库：物料入库、领退补料、成品入库和库存流水。
- 生产人员：工单执行、报工和异常上报。
- 品质：来料/过程/成品质检、不合格与返工处置。
- 选品/市场分析：监控对象、事件复核、需求分析和选品卡片。
- 管理层：产品、生产和选品看板，只读查看与审批。

## 6. 核心数据实体

- 组织与权限：User、Department、Role、Permission、DataScope、AuditLog。
- 店铺与渠道：Store、Marketplace、SellerAccount、Listing、ListingSnapshot。
- 产品：Product、SPU、SKU、Variant、ProductVersion、ProductAttachment、ProductChange。
- 物料：Material、MaterialCategory、UnitConversion、SupplierMaterial、SubstituteMaterial。
- BOM：BOM、BOMVersion、BOMItem、Routing、Operation、QualityStandard。
- 生产：ProductionDemand、ProductionPlan、WorkOrder、MaterialIssue、MaterialReturn、WorkReport、QualityInspection、FinishedGoodsReceipt。
- 选品：WatchStore、WatchASIN、WatchKeyword、MonitorSnapshot、ChangeEvent、DemandTopic、OpportunityCard。

## 7. 实施路线

> 周期是容量估算，不替代 Sprint 验收。业务优先级与实施顺序不同：登录/RBAC 因依赖关系先做。

| Sprint | 参考周期 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| Sprint 0：业务与数据基线 | 2 周 | 产品/物料/生产 As-Is 与 To-Be、编码规则、样本数据、原型、竞品数据源 Spike、MVP Backlog | 老板确认范围；产品/生产 Owner 确认流程 |
| Sprint 1：工程底座与登录 | 2 周 | 前后端脚手架、Maven/pnpm 锁定、数据库迁移、登录、RBAC、审计、5 店基础配置、CI | 可部署；登录/权限/审计验收通过 |
| Sprint 2：产品主数据 | 2～3 周 | SPU/SKU/变体、生命周期、版本、附件、批量导入、ASIN/MSKU/FNSKU 映射 | 样本产品完整导入并可追溯 |
| Sprint 3：物料与 BOM | 2～3 周 | 物料、单位、替代料、多层 BOM、版本审批、用量展开、库存流水 | 代表性产品 BOM 与实际用量一致 |
| Sprint 4：生产执行闭环 | 3 周 | 计划、工单、齐套、领退补料、报工、完工、成品入库 | 一张真实代表工单端到端试跑 |
| Sprint 5：质量与生产分析 | 2～3 周 | 工序、质检、返工/报废、批次追溯、耗用与产量差异、看板 | 关键批次可双向追溯，差异可解释 |
| Sprint 6：选品与监控 | 3 周 | 观察清单、自有 Listing 监控、对标 ASIN 快照、变化事件、上新识别和告警 | 选定样本连续监控且误报可复核 |
| Sprint 7：用户需求分析 | 2～3 周 | 评论/退货主题、搜索需求、趋势、机会卡片和证据追溯 | 产出一批可由产品团队评审的机会卡片 |
| Sprint 8：联调与试点 | 2 周 | 权限、安全、性能、回归、培训、试点与上线方案 | P0 缺陷清零；业务 Owner 与老板验收 |

预计首期完整范围约 **20～24 周**。建议分两次可用发布：

- Release A（Sprint 0～5）：产品、物料、生产闭环，约 13～16 周。
- Release B（Sprint 6～8）：选品、监控、需求分析与试点，约 7～8 周。

## 8. 首期验收指标

### 登录与权限

- 未授权菜单、接口和数据范围拦截率 100%。
- 关键登录与业务变更审计覆盖率 100%。

### 产品与物料

- 产品编码和物料编码重复率 0。
- 已生效 BOM 版本可追溯率 100%。
- 代表性产品 BOM 展开结果与人工标准一致率 100%。
- 批量导入失败必须逐行给出原因，禁止静默丢数。

### 生产

- 工单从下达到完工入库的关键状态完整率 100%。
- 领料、退料、补料、报废和入库均生成库存流水。
- 代表性批次正向/反向追溯成功率 100%。
- 计划与实际耗用、产量差异可解释率 100%。

### 选品与监控

- 监控事件包含来源、采集时间、前后值和处理状态。
- 自有 Listing 严重问题告警不得静默漏报。
- 对标上新结果可人工复核，并记录误报/漏报原因。
- 用户需求结论必须记录时间范围、样本量、证据和算法版本。

## 9. Sprint 0 必须确认的问题

1. 公司生产模式：自制、委外，还是两者并存？
2. “辅料”具体包含哪些类别：原材料、包材、标签、说明书、配件、耗材？
3. 当前产品、BOM、物料、工单和库存分别用什么系统或表格维护？
4. 是否需要多仓库、库位、批次、效期和序列号管理？
5. 生产是否需要工序级报工、质检和员工/班组维度？
6. 首期预计监控多少个对标店铺、ASIN 和关键词，目标更新频率是什么？
7. 5 个店铺是否都具备 Brand Registry/Brand Analytics 权限？
8. 登录采用本地账号还是公司现有 SSO，预计用户数和部门数是多少？
