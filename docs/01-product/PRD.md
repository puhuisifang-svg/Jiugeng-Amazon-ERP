## 1. 背景与目标

公司为工贸一体企业，但首期主动收缩为登录、产品、产品对应辅料、选品和指定 Amazon 店铺上新监控，以尽快形成可试用版本。详细边界见 [精简 MVP 范围与实现方案](MVP_SCOPE_PLAN.md)。

## 2. 用户与场景

- 管理层
- 产品经理/产品开发
- 产品/辅料维护人员
- 选品/市场分析
- 系统管理员

## 3. 核心流程

1. 登录 → 按角色进入产品或选品功能。
2. 产品/SKU → 关联辅料、标准用量和损耗率。
3. 监控店铺 → 快照差异 → 新品事件 → 人工复核 → 选品候选。
4. 选品候选 → 评估 → 通过或淘汰。

异常分支与现状流程待 Sprint 0 访谈确认。

## 4. 功能需求

每项需求必须包含：需求 ID、用户故事、业务规则、前置条件、主流程、异常流程、数据权限、验收标准、优先级和关联原型。

## 5. 非功能需求

- 性能与容量
- 安全与审计
- 可用性与恢复
- 数据完整性和及时性
- 浏览器与终端兼容性
