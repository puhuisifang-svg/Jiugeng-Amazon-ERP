## 1. 已确认规则

- 产品/SPU 编码、内部 SKU 编码和辅料编码均由业务人员手动输入维护。
- 系统不自动生成编码，不使用预设流水号，也不在 Excel 导入后自动回填编码。
- Product/SPU、内部 SKU、Amazon ASIN、Seller SKU、FNSKU、UPC/EAN/GTIN 各自独立，禁止互相替代。
- 同一内部 SKU 可映射 5 个店铺各自不同的 Seller SKU。

## 2. 系统最小校验

- 产品编码、SKU 编码和辅料编码为必填项。
- 三类编码分别全局唯一；重复时禁止保存并明确提示冲突记录。
- 保存前去除首尾空格；空字符串视为未填写。
- 界面新增、编辑和 Excel 导入使用同一套校验规则。
- Excel 新增时必须提供编码；编码为空或重复的行不导入，并返回行号、字段和原因。

## 3. 编码修改与删除

- 删除业务资料采用停用，不物理删除，避免编码被误复用。
- 编码是否允许在建立 SKU、辅料、库存或店铺映射关系后修改，尚待确认。
- 在修改规则确认前，技术设计按“已被引用的编码不可直接修改，需管理员受控处理并保留审计”预留。

## 4. 待确认格式

手动输入不等于任意字符。为避免 Excel、搜索和外部系统兼容问题，仍需确认是否限制为英文字母、数字、连字符和下划线，以及是否统一大小写和最大长度。在老板确认前，不固化具体格式。

## 5. 验收标准

- 系统不会自动生成 Product、SKU 或辅料编码。
- 手工新增和 Excel 导入均能正确保存用户输入的合法编码。
- 空编码和重复编码拦截率 100%，且错误信息可定位。
- 同一内部 SKU 关联多个店铺 Seller SKU 时互不覆盖。
