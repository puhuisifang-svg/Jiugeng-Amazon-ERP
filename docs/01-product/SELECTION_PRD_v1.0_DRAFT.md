# 九更 ERP 选品系统 PRD v1.0（评审稿）

日期：2026-10-26。修订：v1.0 网页核查补充稿。状态：需求方案，待业务确认；不是开发完成或上线声明。
范围：现有“选品管理”四个功能，以及支持选品决策的扩展能力。本文不授权启动开发、购买数据服务或修改现有权限。

## 1. 产品目标与现状

目标：让选品人员从发现竞品/店铺新品开始，持续获得可信数据，形成有证据的评估结论，审核后交接新品开发；不再只有菜单、空表格或人工快照。

2026-10-26 源码核查：已有候选池、店铺监控、上新监控、产品监控页面和相关后端。ERP-018/019/030 的基础持久化不等于真实自动选品可用。特别是现有店铺和产品监控主要依赖人工快照，缺少获批数据源及自动调度。本轮按完整业务目标重新规划，不把旧测试通过视为业务验收。

| 当前入口 | 可复用基础 | 本期重点补齐 |
| --- | --- | --- |
| 候选池 `/selection/candidates` | 候选、评审、证据、状态及开发联动 | 完整评估工作台、可解释评分、利润试算、来源追溯 |
| 店铺监控 `/watch/stores` | 店铺、快照、基线、人工来源适配 | 店铺识别、自动任务、在线商品、数据质量和故障可见 |

## 2. 功能范围与阶段

主链路：登记监控店铺 → 建立基线 → 发现新增 ASIN → 加入候选/产品监控 → 研究与试算 → 评审 → 新品开发草稿。

| 需求编号 | 功能 | 优先级 | 交付边界 |
| --- | --- | --- | --- |
| SEL-01 | 店铺监控 | P0 | 真实数据接入与首个可用闭环 |
| SEL-02 | 上新监控 | P0 | 新品发现、筛选、处理及转候选 |
| SEL-03 | 产品监控 | P0/P1 | P0 基础事实/变化；P1 排名与评价等增强指标 |
| SEL-04 | 候选池与评审 | P0 | 资料、证据、判断、开发交接 |
| SEL-05 | 利润试算 | P0 | 人工有依据录入，明确不是财务利润 |
| SEL-06 | 竞品对比 | P1 | 同站点、同口径的横向研究 |
| SEL-07 | 搜索词分析 | P1 | 获批报告导入起步，再接自动数据 |
| SEL-08 | 市场探索与评论洞察 | P2 | 数据授权后实施，不作为首期假按钮 |
| SEL-09 | 提醒、导入导出、配置 | P0/P1 | P0 站内通知/人工来源；P1 自动摘要 |

P0 分为 P0-A 人工业务闭环、P0-B 真实自动监控。没有数据服务时可以验收 P0-A，但不得宣称 P0 或自动监控全部完成。默认先做 Amazon US，其他站点只保留模型扩展位。

## 3. 全局业务约定

### 3.1 身份、时间与指标

- 商品业务键：站点＋子 ASIN；店铺键：站点＋sellerId。父 ASIN 只做分组，不直接混入子体指标。URL 规范化后存标准链接，不保留跟踪参数。
- 所有观测保留来源、实际观测时间、入库时间、采集任务 ID、完整性和字段来源；人工、外部实测、外部估算、合成演示明确区分。
- UTC 保存时间；界面显示选定站点时区，首次进入明确标注。Amazon US 默认 America/Los_Angeles，夏令时按时区库处理。“今日”按该时区自然日，不使用浏览器本地日期隐式计算。
- “首次发现时间”是本系统观测时间，不等于亚马逊实际上架时间；后者仅在有可信来源时单独展示。
- null 是未知，0 是明确观测为零；字段缺失是未观测。失败不能把旧数据变零，曲线缺口不得用虚构点补齐。
- 售价、Buy Box、促销价分别保存，记录币种和税口径；未知促销叠加关系时不计算“最终到手价”。BSR 必须绑定类目节点，跨类目不比较排名高低。
- 若来源提供“50+”等订单量下界或区间，保存原始展示值、下界/上界、统计窗口、单位和口径，不转成精确值，不用区间端点计算精确环比或利润。区间、估算值、精确观测值必须可区分（W2-04）。
- 竞品真实订单量并非默认可获得。估算销量标注“估算”、供应方和统计窗口；没有可靠数据则隐藏指标或显示“未接入”，不得由评论数推算后写成真实销量。

### 3.3 通用交互

- 所有列表：紧凑筛选 → 工具栏 → 固定表头数据区 → 视口底部固定分页；复用现有 TableViewport、ListPagination、UI_STANDARD。
- 每页默认 20，通常可选 10/20/50/100；产品监控沿用 ERP-030 的 20/50/100，历史接口固定容量时仅展示支持值；切筛选回第一页并清空选择。P0 批量操作仅作用当前页明确选中的 ID；不隐式“全选全部搜索结果”。
- 编辑弹窗固定底部按钮；误点阴影不清空，关闭时复用 UnsavedChangesDialog；保存失败保留输入。并发版本冲突显示“资料已更新，请重新载入”，不覆盖他人改动。
- 空态区分“未添加”“筛选无结果”“尚未获得有效数据”“接入异常”，提供对应下一步；403 与 401 不显示为无数据。
- 未接入能力不显示可点击空按钮。刷新列表仅重新查询；“立即同步”另建后台任务并显示进度，不混淆二者。

## 4. SEL-01 店铺监控 PRD

### 4.1 用户任务与页面

选品人员登记目标店铺，查看最新商品和上新情况，定位同步失败原因。列表筛选：站点、店铺名称/sellerId、监控人（映射负责人）、创建人、标签、启用状态、同步状态。创建人由服务端创建时记录，不可用监控人代替；旧记录未知则显示“—”，不补写当前用户。默认最近更新时间倒序，ID 作为稳定次序。

列：店铺名/别名、站点、监控人、创建人、启停状态、同步状态、在线 ASIN 数、今日新增数、开始监控时间、最近成功时间、备注、数据新鲜度、下次同步、操作。监控开启不等于同步成功，两个状态分别展示。开始监控时间保留首次启用时间，暂停恢复不重置；从未启用显示“—”。未知数量显示“—”，不得伪装成零。

详情页签：商品（在线产品/疑似下架产品）、发现记录、同步记录、设置。桌面用有独立滚动和分页的详情弹窗，窄屏可扩展为全屏；关闭后保留主列表查询、页码与滚动位置。今日新增数进入该店铺、该站点今日的发现记录，在线数进入在线产品；零值可查看空态，未知值不伪装成可点的零。上述跳转为九更交互约定，本次只验证了赛狐“详情”入口。

工具栏显示启用店铺数/允许上限和更新频率（人工模式明确标注）；未勾选时设置监控人禁用。批量分配走店铺既有授权规则、版本冲突和逐行结果；不得沿用到产品监控以绕过其“设置本人负责”限制。行操作统一“详情＋更多（编辑、归档）”，归档确认显示历史保留影响，不直接照搬赛狐“移除”（其恢复机制本次未验证）。

### 4.2 添加、编辑、启停

1. 添加表单：站点必填；店铺 URL 或 sellerId 至少一个；店铺显示名、负责人、标签可填。URL 与 ID 都填但不一致时阻止提交。
   网页核查补充（W1-05）：新增“单个/批量”录入；批量为同一站点、一行一个地址，共用监控人，建议每批最多100行。提交前逐行预览格式错误、重复、站点不符、可新增及剩余额度；空行忽略，重复保留原行号反馈。超额须由用户调整选择，不静默截断；并发提交仍在服务端原子校验额度。失败行保留可重试，成功行不得重复创建。手动输入 sellerId 是九更扩展，不宣称赛狐表单支持。
2. 后端仅解析支持站点的标准地址，规范化 sellerId 后查重；重复返回已有店铺链接。不要为了“解析”直接请求任意用户 URL。
3. 创建成功立即入首次同步队列；展示“待建立基线”，不是立即显示监控成功。来源未配置则展示“待接入”，允许保存但不创建虚假任务。
4. 负责人只能选择启用且具备相应权限的用户；停用人员保留历史显示并提示重新分配。标签最多 20，备注最多 1000 字（建议限制）。
5. 暂停停止后续调度；在途任务完成后可留技术记录，但不得推进暂停后的业务基线或发送提醒。恢复先检查来源资格，再排队。
6. 不提供永久删除；停用/归档保留历史与候选来源。恢复监控采用最近有效基线，长时间中断后的新发现标注“中断期间新增”，不能归为确定今日上架。

### 4.3 采集与商品列表

默认每日一次，任务有随机抖动以避免集中请求。立即同步同一店铺仅允许一个在途任务，建议 15 分钟冷却并提示剩余时间。限额通过后台配置，不把赛狐套餐限制复制到代码。

在线商品显示图片、标题、ASIN、参考售价及币种、评分、评价数、可信来源的首次上架时间、本系统首次发现时间、最近观测；行内“加入候选”“加入产品监控”，并显示已关联状态。批量添加与单条复用相同去重、配额和逐行反馈，不把已监控行当新成功计数（W1-03/04）。

日期筛选有明确字段标签，默认“首次发现日期”；用户可切换“来源首次上架日期”，疑似下架视图可选“疑似下架发现日期”。起止日期按站点时区包含首尾自然日，后端以起日零点至结束日次日零点的半开区间查询；仅一个边界允许单侧查询，起日大于结束日就地报错。ASIN精确查询与日期条件组合；切视图/筛选回第一页并清空选择。赛狐日期输入未明确显示筛选字段，本处为九更消歧设计。

新增“疑似下架产品”（P0-B）：完整快照中不再出现的商品，仅代表该店铺观测缺失，不代表全亚马逊不可售。建议连续两个不同站点自然日的完整有效快照缺失才从在线转入疑似下架；同日重试或立即同步不重复累计；保存首次缺失时间、判定时间、最近出现时间和两次来源任务引用。部分、失败、空结果异常、暂停期间均不累计缺失次数，不清空在线列表。两次之间重新出现则重置计数。阈值为九更建议，需求冻结时确认，未推断赛狐算法。

疑似下架行保留最后有效商品信息并标注其时间，新增“疑似下架发现时间”，不把最后价格标为当前可售报价。后续完整快照重新出现时恢复在线，追加“重新出现”记录，不修改历史首次发现、不新建上新事件、不丢失候选/监控关联。店铺商品出现状态与产品监控的可售状态分开存储。

### 4.4 验收

- 同店铺不同格式链接只创建一条；不同站点不误合并。
- 首次完整快照含 100 个 ASIN：在线 100、上新事件 0。
- 后续完整快照新增 3 个：只生成 3 条事件；重试不重复。
- 空结果、分页缺失、超时、来源失效：旧基线和在线商品不被清空。
- 暂停后不再调度；恢复、中断、并发启停和重启均不制造重复事件。
- 有效基线包含商品A；首次完整缺失仅待确认；次日再次完整缺失进入疑似下架；中间插入失败任务不加次数；重新出现恢复在线且不产生新上新。
- 批量店铺含重复、无效和超额项时逐行反馈；并发新增不突破上限；日期边界、切视图、主列表返回位置和弹窗独立分页可验证。

## 5. SEL-02 上新监控 PRD

### 5.1 列表和详情

定位：九更跨店铺的新品处理收件箱，是对赛狐“店铺列表→店铺详情”的扩展，不声称赛狐提供相同工作台。店铺详情的发现记录与此处复用同一事件数据和操作规则，带店铺及日期条件可互相跳转。筛选：发现日期、站点、店铺、负责人、处理状态、是否已监控、是否已入候选、ASIN/标题。默认待处理优先，再按发现时间倒序。

列：商品图片/标题/ASIN、来源店铺、首次发现时间、来源首次上架时间、参考价格及币种、可得的评分/评价数、处理状态、候选关联、产品监控关联。来源上架日期未知显示“—”；界面将系统发现标为“首次发现（监控上新）”，不得与亚马逊上架日期混为一列。详情展示发现时快照、当前可用数据及来源运行；价格变化不能重写发现时证据。

### 5.2 操作与状态

- 单条/批量“加入候选”：预览站点、ASIN、负责人、选品理由；成功后保存关联。已有候选则链接原候选，不覆盖既有评估；已有淘汰候选显示原因，不自动重新开审。
- “加入产品监控”：按站点＋ASIN 去重；已存在返回目标详情。加入监控不等于已纳入候选，两个关联独立。
- 事件状态：UNHANDLED（待处理）→ CONVERTED（已入候选）或 IGNORED（已忽略）；忽略必填原因，允许恢复至待处理。已转候选事件不可通过“恢复”解除来源链。
- “标记已读”仅影响个人阅读状态，不改变全局处理状态。批量动作逐行返回成功、已存在、权限失败或冲突，可重试失败行。
- 今日新增数按观测日期统计，与是否忽略/已读无关；待处理数另行统计，不混为一个数字。

### 5.3 判定规则与验收

新增集合＝当前完整有效快照 ASIN 集合－上一完整有效快照 ASIN 集合。需另用历史首次见集合去重：曾出现后消失再出现记为“重新出现”，不是新商品。首个基线不产生上新。

事件唯一键至少含店铺、站点、ASIN、事件类型；同 ASIN 在两个店铺可有两条发现证据，但候选只有一个站点商品实体，多来源追加关联。

验收：首基线无事件；乱序/部分失败不推进基线；重复确认只产生一个候选；两个店铺发现同一 ASIN 保留两条来源；忽略不减少客观发现数量；并发处理不覆盖已存在的决定。

## 6. SEL-03 产品监控 PRD

### 6.1 添加与工作台

支持站点＋ASIN/标准商品链接批量输入，建议每批 100、启用目标 1000 的原有额度先保留，实际自动采集容量由数据预算限制。父 ASIN 无法分解时提示提供子 ASIN，不静默虚构子体。

输入支持粘贴多行、回车或逗号分隔；始终提供可见的“批量输入”按钮，双击只可作为快捷方式，不能成为唯一入口。站点先选择；输入提示明确子ASIN，父ASIN拒绝或通过获批来源显式解析后再次确认。

逐行预校验：格式、站点冲突、重复、剩余额度；确认后返回新增/已存在/无效/超额。保存标签、备注、本人负责；关注和列设置按用户隔离。

列表筛选：站点、ASIN 批量精确查询、标题、标签、负责人、个人关注、启停状态、数据新鲜度。列显示商品身份、主要指标、最近成功时间、变化摘要和状态。批量启停、标签追加/移除、设置本人负责均带版本，不允许客户端伪造负责人。

### 6.2 详情逐项实现

| 页签/能力 | 如何实现 | 无数据/异常处理 |
| --- | --- | --- |
| 商品概况 | 展示标题、品牌、主图、五点、站点、ASIN、可售状态和各字段时间 | 未观测显示未知；不抓取任意图片 URL 到服务器 |
| 价格趋势 | 按报价类型、币种画折线，默认近30天，可选7/90天；悬停显示来源与时间 | 不跨币种连线，不把缺口补为0 |
| 排名趋势（P1） | 保存类目节点＋排名，选择单一类目趋势；名次下降数值上升须明确说明 | 类目变更分段，不能与旧类目直接计算涨跌 |
| 评分/评价（P1） | 星级、Rating 数、Review 数分开存储和显示，按观测时间绘图 | 评价数减少也保留事实，不将其截断为0新增 |
| 内容变动 | 标题、五点、主图、价格、可售状态前后值对比，标记变化字段 | 首条有效观测只建基线，不能报“全部改变” |
| 历史快照 | 分页查看完整、部分、失败及不采纳理由，展示实际观测时间 | 失败记录不可被隐藏成“没有更新” |
| 手工补充 | 独立人工观测入口，显著标示来源，保留现有记录能力 | 不覆盖外部自动来源基线，不参与自动报警 |

### 6.3 自动更新规则

默认日频；列表刷新不触发抓取。数据任务执行成功且字段完整才推进对应来源的基线；部分成功可追加观测，但不产生缺失字段变化。晚到旧快照进入历史而不覆盖新事实。

来源切换重建该来源基线，不把不同供应商的定义差异当商品变化。48 小时无有效更新显示“数据过期”，保留最后数据及时间。

### 6.4 验收

重复添加与并发额度保护；三角色既有访问能力不回退；关注隔离；部分字段缺失不触发删除报警；首次观测/切换来源无虚假变化；乱序不覆盖；暂停后不生成新的业务事件；缺少 BSR、销量时界面不显示假曲线。

### 6.5 网页核查补充：列表、昨日比较与字段能力

- 监控开关（启用/暂停）、商品状态（可售/不可售/未知）、同步质量分别显示；不能用一个“状态”承载三种含义。最新变动显示字段类型及发生时间，打开对应前后值证据；无变化与未获取数据区分。
- P0列设置按用户保存：监控状态、图片、标题/ASIN为固定身份列；其余已实现列可搜索、显隐、调整顺序、恢复默认，取消不保存；刷新后恢复偏好。新能力上线不重置用户配置；旧偏好引用失效列时忽略该列并保留身份列。遵循UI_STANDARD，不缩小图片或挤掉操作区。
- P1“对比昨天”在原列表内显示同类型指标的昨日值和差额；区别于§9多商品横向对比。按站点自然日选同来源最后有效观测，只比较相同币种、价格类型及类目节点；缺昨天数据显示“无昨日数据”，不拿最近一次历史冒充昨日。排名用“提升/下降N名”，未知值、区间销量不计算精确百分比；关闭后只隐藏比较展示。
- P1来源可用时增加：优惠价、会员折扣价及适用条件/有效期、大小类节点与排名、Rating评分数、来源上架日期、尺寸与重量。尺寸明确商品/包装口径和长宽高顺序，重量明确净重/包装重，保存原单位并显式转换；口径未知不进入利润履约费计算。没有来源不展示假值，也不因列设置存在而宣称已接入。
- 产品监控保持“设置本人负责/清除负责人”、个人关注隔离。赛狐的创建人、运营字段和任意人员分配仅为参考，不新增产品监控人员操作历史；若需要创建人筛选，先独立确认对ERP-030规则的变更。店铺模块既有创建人记录不受此限制。
- P1可选“关联我的产品”：选择有读取权限的现有自有商品，保存引用及研究用途，不把竞品ASIN复制成自有SKU，不隐式授权读取其订单。未接入自有订单数据时不生成订单趋势。

补充验收：昨日缺数、来源切换、币种/类目改变均不出错误涨跌；列偏好按用户隔离，取消不落地；重复或父ASIN输入有明确反馈；未知尺寸口径不自动参与试算；批量未选择禁用，部分失败只重试失败项。

## 7. SEL-04 候选池与评审 PRD

### 7.1 入池与列表

来源支持人工、上新事件、产品监控，后续扩展市场探索/关键词。必须有站点＋ASIN，理由建议新增时填写、提交评审时必填；产品标题/图片无来源可先留空，不能阻止研究登记。

站点＋ASIN 唯一；再次导入追加来源证据，不自动覆盖负责人、评分或状态。历史只按 ASIN 唯一的模型须先回填 US，再迁移联合唯一键；冲突先出报告，不删除历史候选。

列表筛选：状态、负责人、站点、类目、标签、来源、评分、创建日期；列含产品、状态、评分、资料完整度、利润试算状态、负责人、更新日期。资料完整度不等于商业潜力评分。

### 7.2 候选详情

页签：概况、市场/竞品研究、利润试算、评审记录、证据、关联开发。

| 字段组 | 字段与规则 |
| --- | --- |
| 商品 | 站点/ASIN只读；标题、类目、品牌、图片带来源；站点不能通过编辑偷换 |
| 市场 | 目标客户、场景、主要竞品、季节性、需求证据；未知值允许留空 |
| 差异化 | 主要痛点、拟改善点、供货可行性、试样计划 |
| 风险 | 品牌/专利待核查、类目准入、危险品/认证、尺寸物流风险；结论为待查/可接受/阻断，不输出法律保证 |
| 管理 | 负责人、标签、选品理由、备注、版本号 |
| 证据 | 名称、HTTPS链接、说明、日期、来源快照引用；追加式保存，失效链接不删除历史 |

### 7.3 评分与评审

建议五项 0–5 分：需求证据25%、差异化25%、利润空间20%、供应可行性20%、风险可控性10%。总分＝Σ(单项分÷5×权重)，保留1位小数；未评分显示“未完成”，不自动记零。不设自动通过阈值，评分只是辅助。

每项必须有理由或证据引用；评分规则带版本并在审批时冻结。系统不通过不可得的销量自动打分。

沿用状态：NEW → REVIEWING/REJECTED；REVIEWING → APPROVED/REJECTED；终态不可直接改回。进入评审要求负责人、理由和至少一条证据；通过要求评分完成、有效试算、无未解决阻断风险和审核结论；淘汰必须填写原因。

已通过/淘汰的核心评估冻结，只允许追加备注和证据。重新研究需求先记录为后续版本方案，本期不偷偷新增回退状态。首期沿用管理员/选品角色审批，非强制双人；如需提交人不可自审，另行确认角色与流程。

### 7.4 开发交接与验收

通过时沿用现有同事务事件：创建且只创建一个新品开发草稿，冻结候选资料与本次试算摘要；失败整体回滚。已有历史开发关联保留，不能重复建单。审批不是自动创建 SKU、采购或库存。

验收：四类来源可追溯；并发同商品只入池一次；未完整评估无法通过；淘汰原因必填；提交版本冲突保留输入；开发创建失败审批不落地；通过后资料不会随竞品后来变更而漂移；产品辅料角色不可绕过只读权限。

## 8. SEL-05 利润试算 PRD

用途：判断商业可行性，不等同于现有产品成本核算或财务结算。独立试算快照可引用产品成本模块公开结果，不能直接写其内部成本表。

输入：目标售价及币种、采购成本、包装成本、头程、履约费、平台佣金率、广告率、退货/损耗率、其他单位费用、币种汇率及日期。每个金额明确每件口径；MOQ 单独记录，不与每件成本相加。税口径默认不含税，需确认后使用。

统一转换到售价币种后，设 P 为单件售价，C 为采购/包装/头程/履约/其他单位费用之和，r/a/l 为佣金、广告、损耗率：

- 单件贡献利润＝P×(1－r－a－l)－C。
- 贡献利润率＝贡献利润÷P；P必须大于0。
- 保本售价＝C÷(1－r－a－l)；分母小于等于0时显示不可求解。
- 单价与汇率内部用 Decimal，最终展示两位小数，计算不逐项提前四舍五入；试算快照保留原始精度。

上述为简化模型，不覆盖阶梯佣金、最低佣金、复杂税费；有此情形应改用人工确认的固定单位费用并标注模型限制。缺费用/汇率显示“待完善”，只有用户显式确认无需此费用才能录0；不把平台费率当永久常量。

操作：新增方案 → 填写费用与依据 → 计算 → 对比售价/成本±10%敏感性 → 保存版本 → 指定本次评审方案。自动重新计算不能静默覆盖已审批快照。

验收样例：P=20，C=8，r=15%，a=10%，l=5%，同币种，利润=6、利润率=30%、保本售价≈11.43；缺汇率不能出有效结论；负利润可保存但必须提示；重复保存不重复生成版本。

## 9. SEL-06 竞品对比 PRD（P1）

入口：产品监控“加入对比”；自有商品可选，无自有商品也可建立研究组。网页观察到赛狐对比视图按店铺和竞品ASIN检索，其添加监控表单另有“关联我的产品”入口；本稿无自有商品的研究组属于九更扩展。两种模式应显式命名为“自有商品关联对比”和“独立研究组”，不可让用户误以为必须先绑定亚马逊店铺才能研究竞品。每组建议2–10个同站点 ASIN，明确主研究对象；分组名称必填。

横向比较商品身份、价格类型、类目/BSR、评分/评价数、差异化要点、最近成功时间及来源。默认展示最近可用值并标识时间差；历史对比只使用同一日期窗口和相同定义。超过24小时的数据时间差显示不可直接比较提示。

操作：加/移除成员、排序、选基准、切时间窗、关联候选、导出。移除组成员不删除监控目标；无权读取的目标在服务端过滤。

验收：不跨站点/币种自动排名；BSR不同类目不合并；估算销量不混真实订单；移除后历史研究快照不变；缺值不判为“最好/最低”。

## 10. SEL-07 搜索词分析 PRD（P1）

先支持业务持有且允许使用的报告导入；自动供应方另行接入。搜索词排名不是搜索次数，点击份额和转化份额不是本店转化率。

输入字段：站点、报告类型/周期、开始/结束日期、搜索词、频率排名、前三 ASIN及其点击/转化份额、来源。唯一键为来源＋站点＋周期＋搜索词标准化键；保留原文、不要错误合并不同语言词。

页面筛选搜索词/ASIN、排名范围、排名改善、头部集中度、时间窗；详情展示同粒度历史趋势及关联 ASIN。日/周/月报告禁止直接混成一条可比较曲线。

排名改善＝上期排名－本期排名，正数代表改善；上期缺失不显示百分比。Top3份额只在三项齐备且同报告时求和，不用缺失值0凑数。

操作：保存个人筛选模板、加入研究词库、关联候选、选定 ASIN 入池。单独关键词没有 ASIN 时只生成研究条目，不制造假 ASIN 候选。

验收：导入逐行校验、百分比单位明确、重复报告不重复累加、不同粒度不串期、没有历史不画增长趋势；数据源未接入时展示导入入口而非空市场数据。

## 11. SEL-08 市场探索与评论洞察 PRD（P2）

市场探索（参考W2-08）：页首固定展示站点、完整类目路径、当前市场、数据日期/最近成功更新时间；切换市场清空旧选择并重新查询，旧市场结果不得混入。市场排名与市场评论洞察为不同视图，共用明确的市场上下文。选择站点、类目节点、数据日期 → 查询来源提供的榜单 → 价格段/评分筛选 → 查看商品 → 加入监控/候选。榜单范围必须标明供应方样本及排名类型；不得将本系统监控样本叫做“全市场 Top100”。未取得榜单授权前不开放自动推荐。

评论洞察：输入已获许可的评论数据及ASIN，记录时间窗、去重键、星级、语言；按痛点/场景/材质等主题归类，显示提及数、占样本比例和可追溯证据。主题可多选，比例之和可能超过100%，须说明分母为有效样本数。

网页核查补充（W2-09）：评论页增加正面/负面主题切换、主题选择、主题提及趋势；默认近6个月作为P2建议窗口，必须同时显示确切起止日期、有效样本数和最近更新。按自然月分桶展示提及数和样本占比，缺月份显示缺口而非0；主题与方向切换不混合分母。“主题对星级影响”在九更应写为“提及该主题样本的星级分布/差异”，只能表达相关性；没有已验证方法时不显示因果影响值。点击主题可追溯到获许可样本；无样本显示缺数据原因，不生成分析图或摘要。

相似产品推荐（P2，W2-06）：用户先选择有权限的自有商品或明确的研究基准，再查询获批来源；展示推荐理由、使用字段、来源时间与范围。用户勾选并确认后才加入监控，复用去重和额度校验；空态引导选择基准，不能自动替用户添加。赛狐推荐规则与结果本次未验证，本段为九更设计。

AI 摘要标记为辅助分析，保留样本范围与分析版本，不输出“市场真实占比”或无证据结论。样本少于30条时标记“样本不足，仅供探索”（建议阈值）。重跑产生新版本，不覆盖已被评审引用的旧报告。

验收：重复评论不重复计数；每个主题可追溯至样本；空样本不出结论；不同站点/父子ASIN样本分组明确；授权撤销后停止新增采集，已有资料依约定留存。

## 12. SEL-09 提醒、导入导出与配置 PRD

### 12.1 提醒

首期站内通知：新增店铺商品、商品关键字段变化、数据过期、任务持续失败。个人可订阅，默认不向整个群广播。消息链接到对应事件/目标，已读状态按用户独立。

商品变化事件按目标＋来源快照＋字段组去重；价格阈值建议支持绝对值或百分比，基准为上个有效同币种同类型报价；基准0时不计算百分比。每日摘要按用户＋站点日期去重，暂停或未知值不触发降价提醒。

外部 Telegram/邮件推送是后续独立启用项，需明确收件人与渠道配置，不能默认发送。

### 12.2 导入导出

CSV模板带版本；候选/ASIN批量、人工快照、搜索词报告使用不同模板。导入先预览有效/无效/重复，再确认；请求键保证重放一致。建议每批最多1000行；错误行可下载修正，不要求全部重填。

导出支持“当前勾选”或“全部符合筛选条件”明确二选一；后者服务端重新校验权限并生成快照任务，最多10000行/次，超限要求缩小范围。含来源/币种/观测日期/筛选条件，防CSV公式注入，不导出密钥或越权字段。

### 12.3 数据源和任务管理

管理员页面列出：供应方、覆盖站点/字段、授权状态、额度、用量、最近测试、失败原因、下次任务。凭据仅通过受保护配置引用，不在文档、列表、日志显示。

任务状态：QUEUED → RUNNING → SUCCEEDED/PARTIAL/FAILED/CANCELLED；限流为可重试等待，不显示成功。建议指数退避1/5/30分钟、最多3次且遵循供应方 Retry-After；超过上限留失败并通知管理员。

验收：同事件重复重试不重复发消息；暂停无新消息；用户无权限不能经通知链接越权；CSV空值/换行/公式安全；任务重启可恢复且不重复推进基线。

## 13. 数据与技术实现建议

复用 selection/watch/monitoring/development 模块边界，不建设第二套候选库。前端 Vue＋TypeScript，后端 Spring Modulith＋MySQL；以下为契约建议，开发时与现有接口逐项兼容。

| 对象 | 关键字段/约束 |
| --- | --- |
| 数据源 Source | provider、站点、字段能力、授权状态、配置引用，不存明文凭据 |
| 采集任务 Run | 目标、时间窗、幂等键、状态、分页完整性、重试与错误码 |
| 快照 Snapshot | 观测/入库时间、来源、质量、原始字段、采用/拒绝原因 |
| 店铺 Store | 站点＋sellerId唯一、启停、负责人、标签、有效基线 |
| 店铺商品出现状态 StoreProductPresence | 店铺＋站点＋ASIN、首次发现、来源首次上架日期、最近出现、首次缺失、连续完整缺失次数、疑似下架判定时间及来源引用；不与全站可售状态混用 |
| 商品 Target | 站点＋ASIN唯一、状态、版本；关注单独按用户存 |
| 上新 Event | 店铺＋站点＋ASIN＋类型唯一、发现快照、处理状态及候选关联 |
| 候选 Candidate | 站点＋ASIN唯一、状态、版本、评分版本、负责人 |
| 来源 CandidateSourceLink | 候选＋来源实体唯一，多来源追加而不覆盖 |
| 试算 Estimate | 候选、版本、输入、汇率、模型、计算结果、确认标志 |
| 对比 CompareGroup | 研究组、成员、基准与创建时数据快照 |
| 通知 Notification | 事件、用户、去重键、已读状态 |

接口：保留 `/api/v1/watch`、`/api/v1/selection/candidates`、`/api/v1/product-monitoring` 现有根路径；扩展同步任务、事件处理、试算、对比子资源。新增 `/api/v1/selection/research-keywords`、`/api/v1/selection/sources` 等独立资源前更新权限及范围契约。

读接口统一分页返回 items/total/page/size；写接口带version及幂等requestId。401未登录、403权限不足、409版本/幂等冲突、429频率限制、503来源临时不可用；业务字段错误返回可定位字段提示。

候选批准与开发草稿保持同事务；采集完成的业务事件和待发消息使用事务一致的任务/outbox机制，避免数据落地但消息丢失或发送后事务回滚。调度采用数据库持久任务与租约，不能只靠单进程内存锁。

外部地址只允许已批准来源适配器访问固定主机，限制响应大小、超时和重定向；不请求任意用户地址。验证码/反自动化阻断归为来源不可用，不绕过。限额按供应方额度与成本预算控制。

迁移版本在开发开始时分配下一个可用版本，不写死V45。旧快照、评审、来源链与开发关系不得删除；上线前做脱敏隔离库升级与恢复验证，失败回退应用而不是用旧备份覆盖新业务数据。

## 14. 验收与交付计划

### 14.1 分阶段任务及依赖

1. 需求冻结：确认首站点、字段、试算口径、来源预算和角色；交付字段字典、页面原型与接口契约。
2. P0-A：候选、试算、评审、新品开发交接及人工来源；可进行业务闭环验收，但标注人工模式。
3. 来源验证：确认覆盖/授权/成本，连续7天验证数据完整性、时区与稳定性；未通过不得排为“自动监控已完成”。
4. P0-B：店铺自动任务 → 上新事件 → 产品事实监控 → 站内通知，按上述验收案例验证真实输入。
5. P1：对比、BSR/评分趋势、搜索词报告及自动摘要，按来源支持逐项启用。
6. P2：市场探索、评论洞察和推荐，另立数据成本与效果验收。

不在数据源未定前承诺开发工期。前端、后端、QA、Ops任务可拆分评审，实际共享仓库仍遵守单写入规则。

### 14.2 质量与可用性标准

- 每项功能必须有真实页面操作验收，不接受仅HTTP 200或接口存在作为可用性结论。
- 前端全量quality、后端clean verify、范围/权限契约、MySQL升级/重启持久化；涉及数据结构时执行备份恢复演练。
- 浏览器1280×800、800×600、360px：筛选、详情、弹窗、固定分页和按钮均可操作；保存失败与未保存离开可恢复。
- 三角色逐项允许/拒绝测试；个人关注隔离；匿名拒绝；业务幂等、并发版本冲突、任务断点恢复。
- 建议容量验收基线：100店铺、1000启用商品、10万历史快照；列表接口P95≤2秒（不含外部采集），异步任务提交≤1秒。目标需在测试报告注明硬件、并发和样本量。
- 自动采集试运行7天：计划任务最终成功率建议≥95%；其余失败必须可见且可恢复；所有不完整任务基线误推进=0、重复事件=0。成功率不证明数据覆盖，需抽样对照来源字段。
- 数据质量、费用消耗、失败数量和待处理候选可量化；不得仅用“新增了多少页面”衡量完成度。
