# 用户 角色与权限管理 PRD v1.0 草案

日期：2026-10-30。状态：产品设计稿，待业务确认；本次只输出 PRD，不开发、不调整现有账号权限、不部署。

本功能解决“谁能登录、承担什么职责、能看什么、能做什么”的配置问题。建议将“设置 / 用户与角色”更名为“用户管理”，新增同级“角色管理”；权限配置属于角色详情，不单独增加“权限管理”菜单。账号负责人员身份，角色负责一组职责，权限负责具体业务能力。

## 1 现状与问题

| 已核对的现状 | 对业务的影响 |
| --- | --- |
| 后端只有 ADMIN、PRODUCT_MATERIAL、SELECTION 三个固定角色，角色权限在代码中定义 | 无法自行建立财务、采购、生产、只读等岗位角色 |
| 账号只有一个角色；用户页面通过下拉直接切换角色 | 兼岗需要扩大整个岗位权限，无法清晰组合职责 |
| 页面与后端已有 capability 校验 | 可沿用已有授权基础，但仅增加复选框无法形成动态权限管理 |
| 新品开发、样品与产品共用部分产品权限；客户、订单、发票等也存在共享权限 | 无法承诺每个页面、每个按钮都可独立授权，需要同步拆分后端能力 |
| “设置”页也提供账号列表和恢复操作 | 同一账号存在两套维护入口，分页、删除、反馈等行为容易不一致 |
| 已有本人账号保护、会话撤销、软删除及审计 | 应保留，并补充跨账号并发下的最后管理员保护和角色变更审计 |

依据：`IamTypes.java`、`IamService.java`、`IamRepository.java`、`UsersView.vue`、`SettingsView.vue`、路由与 capability 定义。以下为目标行为，不代表当前系统已具备。

## 2 菜单与页面划分

| 入口 | 责任 | 本次调整 |
| --- | --- | --- |
| 设置 / 用户管理 | 创建账号、分配角色、停用、解锁、重置密码、维护联系方式、删除 | 沿用 `/system/users`，更名并改为列表主导 |
| 设置 / 角色管理 | 建角色、复制角色、配置权限、查看成员、启停与删除角色 | 新增 `/system/roles` |
| 角色详情 / 权限配置 | 为当前角色设置业务能力 | 详情页签，不单独占主菜单 |
| 设置 / 审计日志 | 查询账号、角色、授权及业务变更 | 沿用，新增中文授权事件与筛选项 |
| 设置页 | 本人修改密码、系统安全策略 | 移出重复账号列表；提供“用户管理”入口，保留现有密码及安全设置按钮 |

不继续把角色编辑铺在用户列表下方：两种任务的对象、操作频率和风险不同，混在一起会再次挤压列表。也不增加独立权限字典维护菜单：权限点由系统实现并登记，管理员只配置角色，不能手工创造没有接口支持的权限。

旧链接继续可用，已打开的页签标题与面包屑同步更新。角色详情面包屑为“设置 / 角色管理 / 角色名称”，角色管理可点击返回。本人无用户管理权限时仍可修改自己的密码。

## 3 目标与首期范围

首期目标：管理员无需改代码，即可建立角色、配置权限、给用户分配角色，并准确知道变更会影响哪些人。

首期包含：用户列表整合、自定义角色、权限配置、一个用户多个角色、权限来源查看、角色成员管理、影响预览、立即撤权、审计、兼容迁移，以及支撑独立授权所需的接口权限拆分。

首期不包含：组织架构、部门继承、临时授权、用户单独加减权限、角色继承、显式拒绝权限、授权审批流、SSO、多租户、按店铺/负责人划分数据范围。不得为了后续能力在首期放置无效开关。

“按店铺可见”和“允许进入账单管理”是两件事。首期财务查看权限默认覆盖系统中的全部账单店铺，配置界面必须明确提示；如果业务要求不同人员隔离店铺，须将数据范围纳入开发范围后才能启用该用法。

## 4 角色与授权规则

### 4.1 角色种类

| 种类 | 行为 |
| --- | --- |
| 系统管理员 | 受保护内置角色；系统管理及已登记业务能力全量授权，不允许改权限、停用或删除 |
| 兼容角色 | 迁移现有“产品与辅料”“选品”的准确权限集合；名称标注“系统预置”，权限只读，可复制为自定义角色 |
| 自定义角色 | 允许编辑名称、说明和权限，允许复制、启停、删除，受成员及管理员保护约束 |

复制生成“草稿”，不复制成员、不自动给任何人授权。系统管理员不可复制，避免误建名称普通却拥有完整授权管理权的角色。自定义角色不包含用户管理、角色授权、安全策略管理等系统管理能力；首期仅受保护的系统管理员管理授权。

新角色初始为草稿：名称必填、去除首尾空格、2—50字且不与未删除角色重名；说明最多200字。角色编码系统生成且不可修改。普通角色至少勾选一项业务权限及其依赖后才可启用。无权限草稿可保存但不可分配给用户。

### 4.2 多角色计算

一个用户可绑定多个角色，最多20个；有效业务权限为所有启用角色的并集。没有显式拒绝规则，不做角色优先级排序。删除某一个角色绑定不代表撤销该项权限，若其他角色仍授予该项能力，应明确显示剩余来源。

绑定系统管理员角色时不再混绑其他角色；界面和接口共同校验。启用的业务账号必须至少保留一个启用角色。本人资料与密码管理属于登录基础能力，不需管理员逐项勾选；审计“仅本人”可作为登录基础审计能力保留，但不等于“查看所有人的日志”。

当前登录管理员不能修改自己的角色、停用/删除/锁定自己。系统始终至少保留一名未删除、启用且未锁定的系统管理员；修改其他账号时也要校验，不能只做本人限制。并发操作必须在事务中保证该约束。

### 4.3 权限与依赖

- 默认不授权。菜单可见由页面查看权限推导，不另设一套可能冲突的菜单权限。
- 修改、删除、审批、导出等能力依赖对应查看权限。勾选操作时自动勾选查看，并显示“因已选操作而启用”。
- 取消查看权限时，先列出将同时取消的操作，确认后一起移除；取消操作不擅自删除用户主动选择的其他权限。
- “全选本模块”只影响该模块；“只看已选”“搜索权限”不改变保存集合。不能把搜索隐藏的已选权限丢失。
- 权限点必须对应服务端有效校验；未完成服务端拆分的能力不能伪装成独立复选项。
- 成本、报价等敏感信息默认不随普通产品查看开放；列表、详情、导出、附件、首页汇总及审计快照采用相同授权口径。

## 5 用户管理

### 5.1 列表与筛选

筛选栏：登录名/姓名关键词、角色复选、状态复选；点击“查询”才应用，清空回第一页。角色筛选按“具有任一选中角色”匹配。日期条件如后续增加，统一复用 DatePicker。

字段：登录名、显示名称、角色、账号状态、锁定状态、联系方式、最近登录时间、创建时间、操作。角色多于两个时显示“+N”并可展开查看；空时间显示“—”，不生成虚假最近登录记录。账号启停与锁定分别展示，不混成一种状态。

工具栏仅放“新增用户”；创建表单放弹窗，不长期占用列表上半页。列表操作以“详情”“更多”为主，更多包含编辑资料、分配角色、停用/启用、解锁、重置密码、删除，按状态与保护规则显隐。

账号删除沿用软删除：撤销登录会话，保留业务和审计历史；登录名仍保留，不允许通过重建同名账号继承历史身份。已有成员引用显示历史名称，不因删除变空。

### 5.2 新增与分配角色

新增用户填写登录名、显示名称、找回方式、初始密码和角色。沿用现有密码校验与首次登录改密规则；默认不勾选高权限角色，不把管理员作为默认值。

“分配角色”弹窗显示：当前角色、可选启用角色、变更后权限摘要、增加/减少的权限。必须显式保存，不在列表下拉改变时立刻提交。选择停用或草稿角色返回明确错误并刷新可选项。

用户详情页签：基本资料、有效权限、操作记录。“有效权限”按模块展示只读权限及授予来源，用于回答“为什么这个人能看成本”。不提供个人权限覆盖入口。

## 6 角色管理与权限编辑

### 6.1 角色列表

筛选：角色名称关键词、类型、状态。字段：角色名称、类型、状态、成员数、权限数、说明、更新时间、操作。工具栏“新增角色”；操作“详情”“复制”，自定义角色增加“编辑/停用/删除”。系统角色的限制显示原因，不能做成点击后才失败的无说明按钮。

成员数包含尚未删除的启用及停用账号；权限数按独立权限点去重，不包含分组和菜单节点。点击成员数进入成员页签。

### 6.2 角色详情

页签：权限配置、角色成员、变更记录。顶部只保留名称、类型/状态、说明和必要操作，避免大尺寸概览卡。

权限配置桌面采用左侧模块导航、右侧权限矩阵；左栏约200px，右侧按“功能页面 / 查看 / 新增编辑 / 删除 / 审批或业务操作 / 导入导出”分组展示。没有对应操作的单元格显示“—”，不能用空复选框暗示支持。页内关键词搜索支持功能中文名称；可切换“全部”“只看已选”。

操作列只是展示分组，内部仍可细分，例如采购“提交、取消、收货”分别勾选；不把三个动作合成一个含义模糊的“管理”。模块总复选框支持全选/半选；不因折叠而清空选中状态。

底部操作固定可见：“取消”“保存权限”，显示本次新增/移除权限数。保存前弹出变更确认，展示受影响成员数、增加/移除项目以及撤销会话的影响。不能仅显示“保存成功”而不提示被影响人员。

角色成员页支持查询成员、添加成员和移除成员。添加/移除最终调用同一用户角色分配规则；移除用户最后一个有效角色时阻止提交，并引导先分配替代角色。

### 6.3 启停与删除

| 操作 | 规则 |
| --- | --- |
| 停用自定义角色 | 先预览受影响成员。若使任何启用账号失去全部有效角色，则阻止；先给这些账号分配替代角色，或明确停用账号 |
| 已停用角色 | 不参与授权，不可新分配；成员绑定保留用于追溯，不静默删除 |
| 启用已有成员角色 | 提示会恢复哪些权限及影响人数，确认后生效；不能隐式恢复权限 |
| 删除角色 | 仅允许无成员绑定的自定义角色，软删除并保留历史；有停用账号成员也必须先解除绑定 |
| 修改名称或说明 | 不撤销成员会话；修改权限、角色状态或成员绑定需要撤销相关会话 |

## 7 功能权限目录与业务边界

下表为首期目标目录，开发前须逐项形成“页面—按钮—接口—敏感返回字段”映射。表中的“拟独立能力”是新增设计，不应直接套用现有粗粒度 write 权限充数。

| 业务域 | 拟独立能力与注意事项 |
| --- | --- |
| 首页/工作台 | 查看首页；按已授权模块返回待办与汇总，无权限模块不返回数字或明细 |
| 产品管理 | 查看、新增编辑、删除、导入、导出；报关资料和产品附件沿用对应授权，不借附件链接绕过 |
| 样品管理 | 查看、新增编辑库位、移除；与产品编辑独立，仅按需要读取选用 SKU 的基础字段 |
| 辅料/库存 | 辅料查看、维护、删除；库存查看、入库、出库、冲销、安全库存维护分别授权 |
| 产品成本 | 查看、编辑、发布、导出分别授权，保留现有敏感成本保护 |
| 供应商/采购 | 供应商查看、维护、删除；采购查看、维护、提交、取消、收货等实际动作独立登记 |
| 客户/订单/发票 | 分别控制查看与维护；删除、发货、开票结果维护、附件下载等按实际操作登记，不再仅依赖共享 customers.write |
| 发货工作台 | 今日发货与待发货的查看、维护、转移、确认发货、归档、导出按实际流程授权 |
| 产品监控/上新监控 | 各自查看、添加、编辑、更新采集、移除；只有更新权限才能触发批量更新，不向普通查看者开放采集接口 |
| 候选池 | 查看、编辑评估、提交、审核、删除分开；角色授权不替代业务状态条件 |
| 新品开发 | 查看、维护方案、阶段操作、验收/完成/作废按已有流程登记；不能凭产品编辑权自动取得所有开发权 |
| 样品待开发管理 | 生产端查看已通过事项、维护实际样品进度；不给候选审批权限，也不能看到未通过事项 |
| 财务账单 | 查看、维护、删除、导入导出按真实功能拆分；首期注明“全部店铺”，不存在的功能不显示授权项 |
| 审计日志 | 本人日志、全量日志分别控制；无成本权限不能读取历史成本快照 |
| 系统管理 | 用户管理、角色授权、安全策略管理仅系统管理员；不能通过自定义角色自行提权 |

权限只允许某动作，不保证该动作当前可执行：仍须校验数据状态、负责人业务约束、审批条件与资源存在性。禁止用角色配置绕过“审核通过后进入生产端”等业务门槛。

依赖其他模块基础数据的页面使用明确的最小查询能力，例如维护样品需要选 SKU，但不应因此被迫授权完整产品编辑。实施时对这些依赖给出具体映射并纳入验收。

## 8 建议岗位模板

模板帮助配置，不自动给现有用户换角色；复制后必须查看权限再启用。

| 模板 | 建议默认范围 |
| --- | --- |
| 选品专员 | 产品基础信息只读、监控维护、候选评估维护；不含候选审核、成本或财务 |
| 产品开发 | 开发项目维护及产品资料维护；不自动获得成本发布、候选审核或授权管理 |
| 采购 | 供应商、采购、必要的辅料与产品基础信息；采购收货是否开启由岗位职责决定 |
| 生产 | 样品待开发中已通过事项、样品库位及必要的发货任务；无财务及候选审核 |
| 财务 | 账单、必要的订单与发票资料；首期全部账单店铺范围需明确确认 |
| 业务只读 | 指定模块查看；敏感成本、财务、导出默认关闭 |

首期以自定义和复制现有角色为核心。岗位模板须在第7节对应权限拆分完成后提供，不允许先用过宽角色冒充模板。

## 9 保存 生效与异常反馈

权限保存采用“编辑草稿—检查依赖—预览差异和影响成员—确认保存”。预览不改变权限，确认保存时重新校验版本、成员关系、操作者权限和保护规则。

一次保存要么全部成功，要么全部失败；不得出现角色权限更新了、成员会话未失效或审计没写入的半完成状态。角色具有版本号；他人已修改时提示“角色已更新，请重新加载后确认”，不覆盖对方内容。

角色权限变更、角色启停或用户角色分配生效后，受影响用户的旧会话立即失效，下一次受保护请求不得继续使用旧权限；页面提示“权限已调整，请重新登录”。重新登录获取最新菜单和能力。业务请求在鉴权前已合法进入处理的，按原事务完成；高风险审批/删除/授权提交时需再次校验，授权撤回不回滚已完成业务。

仅修改角色名称/说明不强制重新登录。保存失败保留草稿并显示具体原因；保存中禁用重复提交；未保存离开使用系统统一未保存确认。

旧页面残留、手工调用接口、修改请求参数、直接访问详情链接、附件地址或导出接口均不能绕过权限。没有查看权限的列表、总数、自动补全和首页摘要不得暴露对应数据。

## 10 审计与可追溯性

记录角色创建、复制、权限修改、启用/停用、删除，以及用户角色分配变化。保留操作者、时间、目标角色/用户、修改前后权限与成员差异、变更原因、版本及结果；权限修改和启停/删除需填写原因（2—200字）。

列表显示中文动作和资源，原始编码用于技术追踪；快照不可更新或删除，不记录密码、令牌等秘密。删除角色和用户后仍能查询历史名称及授权来源。

并发版本冲突、禁止修改最后管理员、越权授权等失败有明确原因；失败日志不因业务事务回滚而丢失。权限变更详情与全量授权快照只对管理员或具备全量审计权限者开放，普通用户不能借审计读取他人授权结构。

## 11 数据与迁移要求

建议对象：角色、权限目录、角色权限关系、用户角色关系、授权版本及审计记录。权限目录由应用版本维护，包含编码、中文名称、所属功能、依赖、敏感标识和接口覆盖；普通管理员不得编辑目录编码。

迁移现有三种角色到受保护的内置角色及其关系，用户 ID、登录名、密码、账号状态、业务归属与审计历史保持不变。迁移前后逐账号比较有效权限集合：既不扩大，也不丢失原有业务能力。粗权限拆分为具体动作时，按旧能力实际覆盖范围映射，并保存映射清单。

原角色字段仅在过渡期兼容读取，新的授权关系成为唯一权威来源；禁止旧枚举与新配置各自决定一部分权限。所有正式接口、导出下载及前端守卫统一走有效权限；模拟环境单独标识，不能拿模拟切角色结果代替真实鉴权验收。

迁移可重复执行且不重复绑定。先备份并验证迁移，准备能够识别新角色关系的回滚版本；创建自定义角色后，不允许直接回滚到只认识三个枚举的旧程序。

现有设置页账号维护入口迁到用户管理后，应保留原有停用、解锁、重置密码、联系方式、删除能力，避免“页面统一”造成能力丢失。

## 12 UI 约束与页面示意

统一遵循 `docs/ui/UI_STANDARD.md`。主菜单、标签栏、面包屑保持三行紧凑布局；搜索与工具按钮32px，表单40px；列表使用 TableViewport 和固定底部 ListPagination。

用户/角色筛选中的多选复用 FilterMultiSelect，使用蓝色“全选”、搜索、半选和已选数量；日期筛选复用 DatePicker。权限矩阵是专用配置区，不挤进下拉多选；复选与半选颜色、焦点样式保持一致。

## 13 验收标准

| 场景 | 预期 |
| --- | --- |
| 迁移既有三个角色 | 各账号可见和可操作范围与迁移前一致，无隐式增权 |
| 新建只读角色 | 可看授权页面，编辑/删除按钮不可用，直接调用写接口返回403 |
| 新增编辑权限 | 自动补充查看依赖；移除查看需确认连带撤销，不留下非法组合 |
| 用户分配两个角色 | 有效权限去重取并集，详情可解释每项来源 |
| 移除其中一个角色 | 仅撤销不再由其他角色授予的权限；不误报全部撤权 |
| 查看产品但无成本权限 | 产品页、导出、附件、首页、审计均不泄露成本数据 |
| 生产模板 | 只出现已通过的样品待开发事项，不取得候选审批能力 |
| 修改角色权限 | 影响预览准确；旧会话下一次请求失效，重新登录显示最新权限 |
| 并发撤销管理员 | 至少一名可用管理员保留；保护在后端事务内生效 |
| 停用用户唯一有效角色 | 提示受影响账号并阻止，不能悄悄留下无角色的启用账号 |
| 删除有成员角色 | 阻止并提供成员入口，软删除与历史审计保留 |
| 自定义角色请求系统管理权限 | 接口拒绝，不能仅靠前端隐藏 |
| 两人同时编辑角色 | 后保存者收到版本冲突，原草稿保留，不能覆盖 |
| 保存或会话撤销失败 | 变更整体失败，显示原因并保留草稿，无部分生效 |
| 账号入口整合 | 原有账号操作全部可用，不再有两套账号列表 |
| 手机与窄屏 | 查询、权限选择、差异预览、保存/取消与分页可访问 |

## 14 开发拆分与交付边界

建议作为一个功能版本按三个内部里程碑推进：

1. 权限盘点与模型：冻结真实权限目录、接口覆盖、依赖关系、旧权限迁移映射及管理员保护。
2. 用户与角色管理：动态角色、成员分配、权限矩阵、差异确认、会话生效和审计；完成必要业务接口拆分及菜单/按钮/字段联动。
3. 迁移与验收：真实账号权限回归、越权/并发/失败测试、桌面与手机验收，验证原本地环境部署与回退。

三个里程碑不是三个对用户宣称“已完成”的版本。只做角色列表或复选界面不算交付；对应权限未真正控制接口的功能不得上线。首期不开展数据范围配置，后续如新增店铺/负责人范围，应覆盖列表、详情、统计、附件、导出及后台任务的同一范围校验。

本稿建议确认的产品方向：两个管理菜单；权限配置归角色详情；多角色取并集；系统授权仅管理员；首期功能权限，后续数据范围。本次没有进行开发或修改任何账号授权。


## 2026-10-30 用户确认的角色维护调整

- 系统管理员固定排在角色列表第一行（符合当前筛选条件时）；排序在分页之前执行。
- “产品与辅料”“选品”等预置业务角色允许直接编辑名称、说明、启停及增删权限，不再要求先复制。列表提供“编辑”入口；新增角色仍复用已有创建流程。
- 无成员的业务角色可删除（保留审计和软删除记录）；有成员时先解除绑定，不能使启用用户失去全部有效角色。
- 仅 ADMIN 系统管理员角色保持保护，不允许改名、改权限、停用或删除。权限变化继续执行依赖校验、影响预览、版本冲突保护和成员会话撤销。
- 本节替代4.1节“兼容角色只读”的早期设计；详情面包屑采用 UI 规范中的“详情”。
