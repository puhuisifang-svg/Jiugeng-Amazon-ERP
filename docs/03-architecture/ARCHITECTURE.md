# MVP 总体架构说明

| 字段 | 内容 |
| --- | --- |
| Owner | Backend / Ops |
| 版本 | v0.3 |
| 状态 | In Review |
| 最后更新 | 2026-09-12 |

## 1. 架构结论

首期采用**前后端分离的模块化单体**，不拆微服务。登录、产品、辅料库存、选品和监控保持领域边界，但部署为一个后端应用，以降低内部 MVP 的研发、部署和运维成本。

```text
Vue 3 管理端
      │ HTTPS/JSON
Spring Boot 模块化单体
├── IAM / Audit
├── Product / Amazon Mapping
├── Auxiliary Material / Inventory
├── Selection
├── Watch / Collector Adapter / Scheduler
└── Import / Export / File
      ├── MySQL 8（业务、任务、审计）
      ├── Redis（锁、短期缓存、任务协调）
      └── S3 兼容存储（图片、附件、导入文件、采集证据）

外部：批准的公开店铺监控数据源；5 个公司店铺的 SP-API 自动同步不在 MVP
```

## 2. 技术栈基线

- 前端：Vue 3、TypeScript、Vite、pnpm。
- 后端：Java 21、Spring Boot 3、Maven Wrapper。
- 数据库：MySQL 8；所有结构变更通过迁移脚本管理。
- Redis：只存可重建状态，不作为库存或业务事实来源。
- 文件：S3 兼容对象存储；数据库只保存元数据与对象引用。
- 部署：Docker Compose 起步；CI 执行构建、测试、依赖和凭据扫描。

具体框架小版本在脚手架创建时固定，不在规划阶段追逐最新版。

## 3. 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| IAM/Audit | 登录、会话、账号、三角色、鉴权、审计 | SSO、组织树、多租户 |
| Product | Product、Variant、动态属性、Amazon 目录与店铺 Listing 映射 | 订单、价格、Amazon 库存 |
| Material/Inventory | 辅料、SKU 对应关系、单仓余额与流水 | 采购、生产领料、成本、多仓 |
| Selection | 候选、查重、状态、负责人、来源 | AI 决策、销量预测 |
| Watch | 店铺配置、采集任务、快照、差异、新品事件 | 绕过平台访问控制、实时监控 |
| Import/Export | 模板、校验、批量入库、结果文件 | 任意格式智能识别 |

模块间只能通过应用服务或领域事件调用，不允许跨模块直接修改数据表。

## 4. 关键一致性设计

- 库存余额和流水在同一数据库事务内写入；使用业务请求号保证幂等，并对余额行加锁防止并发超扣。
- 导入采用“上传 → 校验 → 预览 → 确认提交 → 结果下载”，确认前不写业务表。
- 店铺采集以任务实例记录状态；只有通过完整性校验的快照可提升为有效基线。
- 新品事件使用“监控店铺 + ASIN”唯一约束，重跑任务不重复发事件。
- 外部同步不直接覆盖内部 Product、Variant 或辅料主档。

## 5. 安全与数据处理

- 密码使用成熟自适应哈希算法；会话使用安全 Cookie 或等效受控机制。
- Amazon 凭据、第三方 API Key 和数据库密码只存 Secret Store/部署受保护变量，代码和文档只使用 SecretRef。
- 所有写接口校验角色；库存写入、账号管理、产品停用和选品状态变化写审计日志。
- 采集证据设置保留期，并避免保存与业务目的无关的个人数据。

## 6. 部署拓扑

首期最小拓扑：Web、API、MySQL、Redis、对象存储。开发与试点配置隔离；正式上线前至少增加反向代理/TLS、定时备份、健康检查和告警。

Docker Hub 网络与 GitHub 私有远程仍是环境待办，但不阻塞当前规划；完成后才能把工程环境标记为 Ready。

## 7. 延后能力

微服务、消息队列、Elasticsearch、数据仓库、MES/生产、采购、财务、多仓和高级 BI 均不进入 MVP。只有在容量、隔离、可靠性或团队协作出现明确阈值时才评审引入。
