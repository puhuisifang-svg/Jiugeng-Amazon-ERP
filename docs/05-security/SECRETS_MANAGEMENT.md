# Token、Key 与敏感凭据管理规范

| 字段 | 内容 |
| --- | --- |
| Owner | Ops / PJM |
| 版本 | v1.0 |
| 状态 | Approved |
| 生效日期 | 2026-09-12 |

## 1. 核心原则

**项目仓库只记录“凭据元数据和引用”，永远不保存真实凭据值。**

禁止写入仓库、Markdown、聊天、Issue、命令参数、日志、截图或测试数据的内容包括：

- Amazon LWA Client Secret、Refresh Token
- AWS Access Key Secret、Session Token
- 数据库、Redis、对象存储密码
- JWT/加密/签名密钥
- CI/CD Token、Webhook Secret
- 私钥、证书密码、Cookie 和会话令牌

## 2. 允许记录的内容

- 凭据逻辑名称，如 `AMAZON_SPAPI_REFRESH_TOKEN`
- 用途和目标环境
- 系统 Owner 和审批人
- 受保护存储系统名称
- SecretRef/变量名，不包含真实值
- 允许访问的主机范围
- 创建、轮换和到期日期
- 使用该凭据的服务

以上信息统一登记到 [密钥登记表](SECRET_REGISTRY.md)。

## 3. 存放位置

优先级：

1. 部署平台或云 Secret Manager
2. CI/CD 受保护变量
3. OpenClaw Secret Store（仅 Agent 运行确需使用时）
4. 本机系统钥匙串/密码管理器（仅个人开发临时使用）

不得以明文 `.env` 作为团队共享方案。开发机确需本地变量时，只能由受保护存储临时注入，且 `.env*` 已被 `.gitignore` 忽略。

## 4. 生命周期

1. 申请：提交凭据名称、用途、环境、权限和允许访问的主机。
2. 审批：业务或系统 Owner 与 Ops 审核最小权限。
3. 创建：由授权人员在目标平台创建，不在聊天中传递。
4. 存储：写入受保护存储，仅在运行时注入。
5. 使用：禁止打印、回显、记录或复制到其他位置。
6. 轮换：按等级定期轮换，人员离职、泄露怀疑或权限变化时立即轮换。
7. 吊销：服务下线或不再需要时立即撤销，并更新登记表。

## 5. 权限与轮换建议

| 等级 | 示例 | 访问要求 | 建议轮换 |
| --- | --- | --- | --- |
| Critical | Amazon Refresh Token、生产签名密钥 | 最小服务账号、双人审批 | 依平台能力及事件触发 |
| High | 生产数据库、云访问密钥 | 限环境、限服务、全审计 | 90 天或更短 |
| Medium | 测试环境 Token | 限测试环境 | 180 天或更短 |

实际周期须结合平台限制和公司制度确认。

## 6. 泄露响应

发现疑似泄露时：

1. 不在群聊粘贴泄露值或截图。
2. 立即通知 Ops 与 PJM，标记影响系统和环境。
3. 吊销/轮换凭据并隔离受影响服务。
4. 检查日志、提交历史、构建产物和访问记录。
5. 完成影响评估、修复、验证和事件复盘。
6. 若凭据进入 Git 历史，仅删除当前文件不够，必须吊销原凭据。

## 7. 代码和 CI 防护

- 提交前和 CI 执行 Secret 扫描。
- 日志框架配置敏感字段脱敏。
- 测试使用假凭据和 Mock 服务。
- 生产凭据不进入 PR、构建缓存和容器镜像层。
