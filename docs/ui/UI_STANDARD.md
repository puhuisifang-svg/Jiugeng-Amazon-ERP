# 九更 ERP UI 规范 v1.0

状态：ERP-080 本地实现规范；线上发布需项目经理独立验收。适用于以后所有新增及修改页面。

## 原则

以列表和业务内容为主，借鉴赛狐紧凑导航、横向筛选、集中操作的布局，不复制其品牌或业务功能。不得通过整体缩放、隐藏关键条件、裁切按钮、缩小产品图片来压缩界面。

## 全局尺寸

统一使用 `frontend/src/styles/main.css` 中的 `--ui-*` 变量。

| 区域 | 桌面基准 | 规则 |
| --- | --- | --- |
| 主导航 | 44px 最小高 | 保留原权限和键盘操作，菜单不足宽时横向滚动 |
| 最近访问页签 | 32px 最小高 | 不堆叠多个页签行，允许横向滚动 |
| 面包屑 | 28px 最小高 | 13px 字体，保留完整路径和当前标题，不重复放品牌宣传 |
| 页面外边距 | 12px | 小屏 8px |
| 模块间距 | 8px | 禁止无内容的大留白 |
| 搜索控件/列表工具按钮 | 32px 最小高 | 13px 左右字体，按钮文字不可裁切 |
| 搜索/操作卡片内边距 | 8px 12px | 同级操作集中，允许换行 |
| 分页 | 8px 12px 内边距 | 不占用大块独立卡片 |

以上高度是最小值，不是裁切高度。缩放、长文字或无障碍字体放大时允许自然增高。

## 搜索与操作

- 使用现有 `.filter-panel`、`.audit-filters`、`.dashboard-filters`、`.monitor-filters`、`.sku-filter-card`；不得自建大间距搜索卡片。
- 桌面宽于 1000px 时标签与输入控件尽量同排；窄屏恢复上下标签。标签必须可见，placeholder 不能代替可访问名称。
- 保留所有查询项和重置行为，不能为了视觉精简移除业务能力。
- 搜索栏保持 sticky；小屏限制其最大高度并允许内部滚动，保证列表仍可访问。
- 工具栏使用 `.material-toolbar`、`.page-actions` 或 `.monitor-toolbar`，按钮可换行；主操作突出，次操作使用系统次级样式，危险操作仍需明确确认。
- 状态成功反馈使用 toast；阻断性错误可保留内联信息。不得静默隐藏错误来省空间。

## 列表、表单与弹窗

- 列表沿用 TableViewport 单一滚动容器及固定表头；不得通过外层 overflow 裁切操作列。
- 保持产品图片已有尺寸及 contain 展示，保留点击预览；不得因紧凑化改回裁图。
- 编辑表单仍采用现有 40px 控件及清晰分组，不将列表密度强制套用到全部输入场景。
- 产品编辑遵循 ERP-079 左父体、右 SKU 布局，900px 以下上下排列；弹窗底部操作可见。
- 触屏场景需检查实际点击可用性；不允许小于 24px 的点击目标。保留键盘焦点、标签及跳转到内容入口。

## 验收与维护

- 每次 UI 修改至少验证桌面 1280×800、窄屏 800×600、手机宽度 360px；检查横向溢出、菜单/面包屑、查询、按钮换行、表头滚动和弹窗。
- 共享样式变更需运行 `pnpm quality` 和 `git diff --check`；业务逻辑变化还需对应行为测试。
- 纯尺寸修改必须以浏览器验证为依据，不能以 jsdom 断言冒充视觉验收。
- 新页面复用全局变量和公共类；若必须偏离，应在任务记录说明理由，并同步更新本规范。功能权限、数据和 API 合约不得受布局调整影响。
